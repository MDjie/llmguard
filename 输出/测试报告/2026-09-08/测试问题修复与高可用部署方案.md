## 两地三中心部署

采用同城 A、B 双生产中心与异地 C 灾备中心。各中心独立 Kubernetes 集群和控制面，中心内跨至少三个故障域部署，避免将一个 Kubernetes/etcd 仲裁集群跨广域网拉伸。A、B 应用可同时接流量，数据库保持单写，C 平时不接生产写流量。

入口：GSLB/DNS 按中心就绪状态调度，中心内负载均衡分配到多副本网关与控制台。无状态服务采用同一镜像摘要、密钥配置、会话存储和签名策略版本；默认至少三副本，配置 PodDisruptionBudget、滚动更新零不可用、拓扑分散和伸缩。工作进程至少双副本，继续使用数据库事务领取任务、幂等键、心跳与重试；严禁复制队列后重复产生外部副作用。

数据：PostgreSQL 同城跨中心同步备库，使用明确要求同步确认的策略以保护已确认提交；异地采用异步流复制和 WAL 归档/PITR。两个同城中心发生网络分区时，必须以单一写入授权与 fencing 隔离旧主，不能仅根据探针失败就提升另一中心。同步备库不可用时优先拒绝写入；降级为异步须明确接受 RPO 变化。Redis 不作为唯一持久化来源，Kafka、对象存储、审计链分别做复制与校验，搜索索引可重建。

C 中心常备控制面、密钥恢复能力、应用镜像和检测模型；复制作业、数据库和对象存储状态保持可观测。切换顺序：确认故障 → 隔离旧主写入 → 记录最后提交/回放 LSN 与对象版本 → 提升灾备数据层 → 启动必要检测服务 → 核验策略签名、租户隔离与审计 → 灰度切流 → 对账补偿。回切必须重新建立复制并验证一致性，禁止双主同时写。

容量按任一生产中心退出后剩余中心承担峰值负载规划，批量评测单独限额，不挤占在线请求。目标：同城已确认数据库事务 RPO=0，中心级 RTO≤5分钟；异地 RPO≤15分钟、RTO≤30分钟；月可用性目标99.99%。这些是设计和演练验收目标，不代表本地代码测试已证明达标。

## 异构算力

业务网关与检测接口和设备驱动解耦。按 CPU、NVIDIA GPU、Ascend NPU 建立独立资源池，设置节点标签、设备插件资源请求、污点容忍、模型挂载与不同运行时镜像；同一逻辑检测器必须固定模型摘要、词表、阈值、输入输出协议及精度验证集。不能仅修改 GPU 资源名就声称兼容 NPU。

优先同中心同类资源，跨设备切换仅允许通过兼容性与检测质量门禁的后端；记录模型版本、设备类型、时延、超时、降级原因。正则和关键词可在 CPU 执行，必须依赖语义检测的策略在算力耗尽时返回明确失败或人工复核，不能静默放行。国产平台需现场核验驱动/CANN/算子、镜像架构、性能和错误率。当前适配矩阵与 Helm 资源配置作为扩展基础，交付模板而不虚构硬件认证。

## 样本导入与隔离

TXT 每个非空行作为一个攻击输入；JSON 数组或 JSONL 每条记录包含 title、category、inputText，可选 outputText、expectedAction、expectedDimensions、severity。提供模板，UTF-8、单文件5MiB、最多1000条、单方向32768字符。先在服务端预览校验，返回行号、错误说明、重复数量；确认提交再次校验，存在错误则整批不写入。文件内容视为不可信测试数据，禁止执行样本指令、网络链接或上传到业务模型。

批量导入与执行解耦：导入到当前租户/应用验证集，再提交签名策略评测任务。评测结果提供输入/输出方向、实际与预期动作、风险分数、成功失败状态和追踪标识。检测服务如调用判别模型应限制为获准的内部检测后端，并通过网络策略禁止访问业务推理端点。纯文本单条继续复用验证样本表单；截图中最多10轮对话及图片检测按既有对话/多模态入口验收，不能据文本批量导入验收推断其全部达标。

## 权限与运维

| 角色 | 管理范围 |
| --- | --- |
| 系统管理员 | 用户、平台、部署巡检与全部授权操作 |
| 安全管理员 | 维度规则、样本、检测运营和事件研判；不获得平台运维权限 |
| 审计管理员 | 审计查看与导出；不能修改检测规则 |
| 业务操作员 | 检测使用、策略读取、历史查看；不能修改规则 |
| 应用开发者 | 应用集成、凭证管理及策略读取；不能修改规则 |
| 只读用户 | 授权数据与策略只读 |

CPU 指标明确区分进程/主机/容器口径；本地巡检只能代表当前实例，集群节点依赖 node-exporter/设备 exporter 等真实遥测。数据库、Redis、Kafka、对象存储、检测服务、任务积压、证书有效期及复制延迟统一接入 Prometheus/Grafana；配置不可用或采样过期展示未知/异常，不得使用随机或演示数据代替。

1. 单元与接口回归覆盖表单契约、重复编码、规则零值、正则、启停、ID/编码一致性、租户隔离、无权限写入拒绝、导入错误和重复、评测输出方向、问答可见性与未留存情况。
2. 执行 TypeScript、修改文件 lint、相关既有测试及构建；如发现原有未提交改动相关失败，单独记录。
3. 在测试环境用实际登录会话走完报告复现步骤，核对请求状态码、持久化结果与中文错误。数据库、原文留存配置和监控数据源属于环境前提。
4. 以版本化镜像与配置灰度发布，回滚应用与配置，保留已导入样本及审计记录。策略草稿变更须经发布流程生成新签名包；旧兼容引擎缓存最长30秒，新运行副本不得越过签名策略发布。
5. 三中心现场分别演练 Pod、节点、中心断电、同城网络分区、异地提升、异构后端失效及恢复，保留流量、LSN、样本结果、审计与对象版本证据，量化实际RPO/RTO。
