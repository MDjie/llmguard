## P0 完成后的操作

1. 固定一份输入 JSONL。正式效果评估使用完整的适用数据或独立留出集，诊断抽样不作为最终验收。
2. 准备 P0 修改前的 B0 代码版本及其策略快照。在冻结 checkout 中运行 B0。历史策略快照配上当前代码，不等于改动前基准。
3. P0 版本冻结后，由负责 P0 的任务导出同格式策略快照，在该版本运行同一份输入。保持超时和网络模式一致。
4. 用 compare.ts 比较两次结果，查看 FN→TP、TP→FN、FP→TN、TN→FP，以及 UNKNOWN 转移和正常内容送审/降级情况。
5. 对每个数据集、方向和关键风险桶查看分母、Wilson 95% 区间及未知结果上下界，再判断是否达到约定目标。

在对应冻结 checkout 的项目根目录执行：

```powershell
pnpm exec tsx scripts/independent-acceptance/run.ts --input <同一份数据.jsonl> --snapshot <该版本策略快照.json> --out <不存在的新结果目录> --name B0 --timeout-ms 60000
pnpm exec tsx scripts/independent-acceptance/compare.ts --baseline <B0结果目录> --candidate <P0结果目录> --out <不存在的新对比目录>
```

若策略包含分类器或裁判，默认离线模式会拒绝启动，不会静默移除模型。真实模型测试需显式 `--allow-model-network`，按项目方式提供凭证，并先用较小 `--max-cases` 验证预算与调用。此模式允许项目运行时访问网络，不是目标白名单；本次交付未执行。

本地权重或动态加载资产可用重复的 `--asset` 参数纳入内容指纹。静态导入的 JSON 分类资产已经自动包含。代码指纹覆盖未提交修改，不只记录 Git commit。

## 解释范围

烟测使用历史快照，其中配置 7 个检测器、81 条规则，38 条样本均返回 ALLOW。这个结果用于验证工具执行路径，不能称为完整 P0 配置的成绩，也不能外推产品总漏报率。

该工具测试的是本地项目正式引擎及指定策略。未验证线上鉴权、HTTP 网关、流式出口和最终内容释放；所有结果明确标记 transportEnforcementVerified=false。输出转换和复检信息仅按实际发生情况记录。

代码/策略/数据/显式资产在运行前后检查，发生变化的结果不能参与验收。该机制检测净变动，不锁定工作区，不能替代冻结 checkout。进程中断留下 RUNNING；当前版本不做断点续跑，应事先拆成稳定批次或用新目录重跑。

已有引擎提供节点级执行/跳过轨迹及实际命中的规则；工具不伪造所有未命中规则的排除原因。更细的规则内部分支观测需与 P0 任务单独协作。
