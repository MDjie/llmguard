## 1. 已解决的问题

| 问题 | 修复后的行为 | 实际修改位置 |
| --- | --- | --- |
| 单路强制拒绝被联合 ALLOW 覆盖 | user、OCR、二维码、ASR、字幕、帧 OCR 任一路 BLOCK 均保留；视觉、分析失败、信任及覆盖约束共同合并 | `src/lib/multimodal/fusion.ts`、`src/lib/media/timeline-fusion.ts` |
| 只保留联合分支或单个时间簇的证据 | 各分支按自己的 spans 映射，媒体遍历所有联合时间簇，再按映射后的标识去重 | 同上 |
| 重复词或不同对象命中难定位 | 保留 detectorId/version、ruleId/version、来源对象、视图、区域、局部文本区间、时间及帧号；继续仅保留 HMAC/脱敏表达 | 同上 |
| SAFE_RESPONSE 在多模态中盖过人工审核 | 统一集合约束：BLOCK 优先，审核要求不被替代响应取消，MASK/REWRITE 保留复检要求 | `src/lib/guard-engine-v2/action-constraints.ts`、`aggregate.ts`及两个融合入口 |
| 融合子判定固定为 INPUT | context.direction 兼容透传四种检测方向；现有 worker 显式 INPUT | 两个融合入口及两个 worker |
| 缺失模态被占位符参与业务检测 | 返回 MODALITY_NOT_APPLICABLE，不调用检测器，不声称完整证据；必需分析/覆盖约束仍有效 | 两个融合入口 |
| Windows 契约生成与源摘要漂移 | 自有契约固定 LF，三个生成器将 CRLF 规范为 LF 后计算摘要；生成多语言产物同步，兼容基线保持原值 | `.gitattributes`、三个 generator、gateway-v2 生成产物 |
| 全量验证的锁文件摘要和测试运行器问题 | 锁文件保持 main 的 LF 原摘要；离线包的 5 个现有测试纳入 Vitest | `.gitattributes`、`tests/acceptance/gateway-offline-bundle.test.mjs` |

动作约束只描述所需处理，不等同于原文、派生文本或原生媒体的释放许可。已有网关的 MASK、REWRITE、SAFE_RESPONSE 必须继续通过复检和执行证明。

## 3. 集成环境与结果边界

运行环境为 Node.js 24、pnpm 11.19.0、本机隔离 PostgreSQL 数据库以及重新编译的 Java 网关。控制端、模型和对象接收器均为本次工程测试服务；测试期间使用合成内容和 TLS 模型接收侧断言，没有调用客户模型或生产请求。WINDOW 资格为 ENGINEERING，不属于独立模型质量批准。

此次新增数据库初始化检查只在随机新建的工程数据库执行，并在结束后删除该库。既有隔离代理数据库予以保留；测试资格文件恢复原值。临时进程停止后恢复 Next 自动修改的类型引用，避免将测试环境路径混入代码变更。

全量单元和工程集成通过证明本批修复与现有功能兼容，不证明真实音视频识别率、金融误报率、180 天容量、HA、长稳或完整部署已经达标。时间命中提示目前沿用分析器片段时间，局部文本区间采用 UTF-16 左闭右开索引；它不是逐词 ASR 对齐。
