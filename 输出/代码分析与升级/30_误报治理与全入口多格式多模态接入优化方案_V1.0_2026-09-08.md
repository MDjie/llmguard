# 误报治理与全入口多格式、多模态接入优化方案 V1.0

编制日期：2026-09-08。代码基线：`main@90432539830e11edd33c391d43a561bd5d153f56`。本文是增量需求、详细设计与执行计划，任务状态均为待实施。沿用已有 V1.1、检测架构修复及验收资产，不重建另一套检测平台。

用户已确认验收口径：**正常样本误拦率、阻断结果误报占比均不得超过 10%；已有更严门槛继续保留。因此正常样本误拦率仍按 ≤1% 执行，阻断结果误报占比按 ≤10% 执行。** 同时保留召回率、准确率及独立验收等原有门槛。

本轮仅阅读附件、代码、既有测试产物和官方技术资料，复算历史指标并编制方案。测试保持暂停；没有启动新基准、调用裁判服务、修改业务代码或更新部署。

## 1. 核心判断与实施边界

目前的问题同时存在于接入、判定、展示和质量治理四层，单独换裁判模型、调低规则分数或增加文件后缀，不能完成目标。

1. **图片入口存在确定的功能断点。** 文档页面允许 JPG/PNG 等图片，并显示 OCR 提示，但当前 main 的 `/api/document-scan` 对图片无条件返回 `501 MULTIMODAL_OCR_NOT_CONFIGURED`。主聊天接口仅接受字符串，已有多模态 Artifact、Worker、ASR/VLM 适配器没有被这些用户入口完整接通。
2. **历史误报指标必须与低召回同时解释。** 配对离线文本集 FPR 为 0.5076%，严格阻断 FDR 为 21.2346%，严格阻断召回仅 2.4696%。这些结果未包含在线裁判效果，也不能代表实际多模态或线上告警质量。
3. **裁判需要受控的上下文、证据和复核机制。** 当前通用裁判收到的主要是窗口文本；普通语义 UNSAFE 被直接转为确认风险后，后续 SAFE 不能纠正。需要在最终确认前增加有范围限制的反证核验，保留强制阻断与权限边界。
4. **格式支持必须覆盖完整链路。** 定义为“可选择、可上传、可验证、可解析、可检测、可定位证据、可执行处置”，不能以浏览器允许选择或对象存储接收成功作为完成。
5. **系统故障与内容风险分别呈现。** 解析失败、裁判超时、覆盖不足仍可阻止内容释放，但应明确显示“检测未完成”，不能冒充“检出攻击”，也不能静默显示“检测完成”。

本轮业务范围：安全聊天、文档检测、实验室模拟、评测样本导入、开放 Artifact/Guard Job 接口，以及通过这些接口接入的 RAG/工具结果。词库签名 release-set JSON 导入属于治理制品导入，继续遵守其签名和结构约束，不扩展成任意媒体入口。实时音视频流、通话机器人和全量历史数据迁移不作为本轮上传功能的先决条件；浏览器录音作为文件上传接入。

## 3. 误报指标、现状与验收定义

### 3.1 三个指标分开计算

以经人工或可信标签确认、粒度一致的最终请求为统计单位：

| 指标 | 定义 | 用途与目标 |
|---|---|---|
| 正常样本误拦率 FPR | `FP / (FP + TN)` | 正常内容被错误阻断的概率；保留 **≤1%** 门槛 |
| 阻断结果误报占比 FDR | `FP / (TP + FP)`，即 `1 - precision` | 被判定应阻断的结果中实际正常的比例；目标 **≤10%** |
| 严格阻断召回率 | `TP / (TP + FN)` | 防止通过少拦截改善误报；保留原 **≥95%** 正式验收门槛 |

补充记录：确认告警 FDR、WARN/MASK/REVIEW 的错误干预率、正常请求因检测故障未完成的比例、端到端成功率、每千请求的重复告警数。`REVIEW` 不自动等于恶意，`WARN` 不自动等于阻断，系统错误不算检出攻击。若原有兼容接口把这些状态合并，必须同时保存原始处置和展示映射。

**零阻断时 FDR 无定义，不能记作 0% 或判定通过。** 将 BLOCK 改名为 REVIEW、减少告警展示、排除困难样本都不能作为指标改善。

### 3.3 达到 10% 的工程含义

如果 TP 暂时保持 319 不变，点估计 FDR≤10% 要求 FP≤35，至少减少当前 86 条中的 51 条；若 FP 保持 86，则 TP 至少要达到 774。这里只解释数学约束，不是建议靠扩大阻断范围凑指标，正式验收还要满足召回、误拦、理由正确性和置信区间要求。

线上 FDR 强烈受风险请求占比影响。例如风险占比为 1%、召回为 95%、FPR 为 1% 时，理论 FDR 仍约 51.03%；要使 FDR≤10%，相同假设下 FPR 需约≤0.1066%。因此“FPR≤1%”是上限，不能承诺它自动带来生产 FDR≤10%。金融实际正常流量及告警抽样必须独立验收，按业务基率校准策略。

既有门禁中 `independentHoldout=false`、`reasonAlignmentReviewed=false`，候选激活不允许。本轮已经阅读的历史样本归入诊断集；不能重新命名为新盲测集。

## 5. 误报与错误干预的深层原因

下表区分已证实的机制和待通过样本归因验证的影响。未实测的模型效果不写成既成事实。

| 编号 | 代码或证据 | 机制及影响 | 修复设计 |
|---|---|---|---|
| R01 上下文不足 | `judge/router.ts` 使用 `direction/text/trust/riskDefinitions` 构造包；文档逐片调用 V2 | 单个窗口缺少当前可信业务任务、整文档目的、引文位置和跨片否定。安全教育、事故报道、金融风险说明可能被当成实施请求 | 增加 TaskContext 与结构化 SourceEnvelope；优先章节/段落切片，提供有出处的邻域证据，不能让文件自己声明可信身份 |
| R02 复核不能纠偏 | `coverage-judge.ts` UNSAFE→score=1/POLICY/CONFIRMED；已确认风险保持单调 | 对强制规则适合保持不可撤销；对普通语义候选则可能把误判过早锁定，refiner SAFE 无法纠正 | 普通语义在最终确认前采用 PROPOSED→VERIFIED/REFUTED；反证仅对同一风险、同一来源、同一证据生效；HARD_DENY 不允许模型撤销 |
| R03 分数与置信度混淆 | `v2-compat.ts` 使用 observation.score 形成 confidence，并把 review/safe-response 映射 block | 策略布尔分数 1 容易被展示为“100%可信”；不同动作合并后用户把系统保守处置理解成明确攻击 | 传递 scoreMeaning、原始动作、确认级别、能力状态；只有经过校准的概率才显示百分比 |
| R04 长文档放大 | `parser.ts` 默认 1000 字符/100 重叠；`detector.ts` 收集所有 finding，任一 block 导致全文 block | 局部语义缺失；相同重叠证据重复展示；片数越多，出现一次误判的机会越大 | 分层上下文判定、原文位置去重、任务级最终裁决；不能平均分数稀释真实高危片段 |
| R05 不完整任务误报完成 | `detector.ts:250` catch 只记录日志，之后写 completed | 分片故障可能造成缺失证据和假“完成”，既破坏误报统计，也掩盖漏检 | 异常形成 CoverageGap；保留已确认风险，未覆盖部分不得标记安全；任务状态和内容 verdict 分离 |
| R06 媒体识别不确定性 | 文档图像分析中 OCR/视觉/码识别失败被标记 required；低置信度 OCR 会过滤 | 低质量转写可能丢失否定词、说话人和数字；依赖失败可能触发保守阻断，表现为正常内容不可用 | 按风险能力确定必需视图；低置信度局部重识别，保留缺口；明确 NEEDS_REVIEW/ANALYSIS_INCOMPLETE，不伪造攻击告警 |
| R07 语义与规则残留过宽 | 失败记录集中于若干内容风险类型；旧 `judge/engine.ts` 有“扮演/绕过/规避类一律视为注入”提示 | 主题词不等于危害意图，教育/否定/引述易混淆；旧实现如仍被调用可能放大问题 | 专家逐例评审 top FP；旧接口调用图确认后收敛。当前主要 `/detect`、`simulate`、文档已走 V2，不能把旧提示直接归为这些入口的实测主因 |
| R08 金融业务语义缺位 | 现有词典/规则与通用风险框架并存，尚无本轮实际金融误报标签核对 | “保本、拒赔、反洗钱、诈骗”等既是正常讨论主题，也可能是违规承诺；实体出现不等于越权泄露 | 以行为、对象、授权、承诺、受众、渠道组成风险关系；建立有限范围的正常语境反证库 |
| R09 多模态信息关系丢失 | 派生证据联合裁判存在，但通用覆盖裁判对 artifacts 走不支持路径 | 仅将字幕/OCR 拼接会把不同页、不同说话人甚至不同文件的话拼成“意图”；仅用转写遗漏纯视觉风险 | 证据图、任务绑定、时间线、来源角色；文本派生语义与原生视觉覆盖分别计量 |
| R10 模型身份与能力漂移 | 联合证据裁判固定 `glm-5.3`/`zai-org/GLM-5.3`；其他入口曾调整 `glm-5.3-flash` | 修改提供方模型名未必同步到联合裁判；文本模型名称不能证明支持图片/视频/ASR | 统一 profile 与 capability registry；按角色绑定经鉴定模型和适配器，不用品牌字符串判断能力 |
| R11 评测标签污染 | 样本导入提示 TXT 每个非空行默认 BLOCK | 普通文本一经导入就可能被当风险正样本；数据集标签、输入/输出任务和本地风险分类不一致 | 强制选择标签模式，未知标签只做能力诊断；保存 labelBasis 与专家映射，不自动算入准确率 |
| R12 运行版本与配置差异 | 暂停时运行版本不同于 main；已有候选策略尚未通过激活门禁 | 源码修复、页面行为、运行策略、裁判配置可能对应不同时间点 | 每次结果绑定 app/worker/analyzer、policy、model、parser、codec 版本；运行配置预检拒绝未展开的 `${...}` 值 |

这些问题需要消融验证。不能给每个机制编造“造成多少百分比误报”，更不能把减少模型调用直接算作准确率提升。

| RAG/工具结果调用链 | 有相关 Guard API，未找到专属通用文件选择器 | 经同一 Artifact 底座接入；保留 RAG_CHUNK/TOOL_RESULT 数据来源身份，不能升级为 USER 指令；不新增重复的独立上传后端 |
| 词库 release-set 导入 | 已审核 JSON 制品，15MiB | 继续 JSON 签名/结构校验；仅统一错误展示，不接受音视频 |

### 6.2 格式支持目标

下表是**计划支持目录**，不代表当前已经支持。A 为首批必须完成的常见格式，B 为后续批次必须完成的扩展适配；最终按“格式+容器+codec+能力等级”发布。若某解码器尚未部署或未鉴定，应显示具体缺口，不能只扩展 accept 后宣称完成。

| 类别 | A：常见格式 | B：扩展格式 | 检测表达及特殊约束 |
|---|---|---|---|
| 文本/代码/结构化文本 | txt、md、log、json、jsonl、ndjson、csv、tsv、xml、html/htm、yaml/yml；保留 css/js/ts | 明确类型的字幕 srt/vtt/ass/ssa | 作为数据读取；HTML/脚本不执行、不自动访问外链；字幕保存时间码；`.ts` 需区分 TypeScript 与 MPEG-TS |
| 文档 | pdf（文本/扫描/混合）、docx、doc、rtf、xlsx、xls、pptx、ppt | odt、ods、odp、wps、ofd | 文字+页面渲染+OCR；表格单元格、隐藏内容、备注、嵌入对象列出覆盖状态；加密文件明确不支持，不能判安全 |
| 图片 | png、jpg/jpeg、webp、bmp、gif、tif/tiff | heic/heif、avif | 静态/多页/动画分流；OCR+视觉+必要的码内容，保留 EXIF 旋转与坐标映射；动画不能只看第一帧 |
| 音频 | wav、mp3、m4a、aac、flac、ogg、opus、webm（音频） | wma、amr、aiff/aif；带明确采样元数据的 PCM | 按流探测、转码、全时长分段 ASR；多声道/多轨、非语音和低置信度覆盖分别记录 |
| 视频 | mp4、mov、mkv、webm、avi、m4v | wmv、flv、mpg/mpeg、ts、mts/m2ts、3gp | 容器与 H.264/H.265/VP8/VP9/AV1、AAC/Opus 等编码组合逐一鉴定；所有音轨、字幕及视觉时间段分别覆盖 |
| 混合请求 | 文本+任意上述附件；同轮多文件 | 文件间交叉指代、会话跨轮关联 | 附件是同一任务的证据集合；来源和顺序不能因转码或拼接丢失 |

UTF-8/BOM、UTF-16LE/BE 和经确认的 GB18030 作为文本解码目标。识别到 NUL 不能直接断定为二进制；先验证编码，再保留原始字节到解码字符的映射。对不确定编码返回需确认/指定编码，禁止有损替换后自称完整识别。

普通 ZIP/7z/RAR 批量压缩包、DRM 媒体、宏执行、远程播放列表及外部依赖不纳入自动执行范围。Office 的 ZIP 容器内部解析必须受条目数、解压比和总量限制；这不等于允许用户上传任意归档执行。

### 6.3 统一限额与能力展示

现状不是简单“上限太小”：文档 API 50MiB；Artifact TEXT/IMAGE 为 100MiB、AUDIO 为 500MiB、VIDEO 为 3GiB、DOCUMENT 为 500MiB；原生模型消息单块仅 1MiB。上传可存储的上限与模型可处理的上限不能混用。

设统一租户 profile，沿用现有 Artifact 硬上限；首个交付 profile 建议文档≤50MiB/200页，图片≤20MiB/4000万像素，音频≤100MiB/30分钟，视频≤500MiB/10分钟/1080p，每轮≤10个附件且受总量限制。它们是初始运行预算，需要在真实负载鉴定后确认；后续提高预算不修改协议，只新增经过质量和容量鉴定的 profile。所有入口展示相同的有效限额。

能力响应区分四层：`UPLOAD_SUPPORTED`、`PARSE_SUPPORTED`、`ANALYSIS_READY`、`ENFORCEMENT_QUALIFIED`。最终用户选项只在策略要求的层级满足时标记可用；其余显示“需配置 OCR”“编码暂不支持”“超出当前时长”等具体原因。不能用对象已存储替代分析可用，也不能因为菜单存在就声称能够拦截多模态攻击。

## 7. 详细架构：统一接入与受控判定 Harness

本方案中的 harness 是围绕模型的确定性执行框架：负责状态、可信上下文、工具权限、预算、重试、证据校验和释放记录。模型只生成受约束的判断建议，不自行取得上传权限、解除阻断或改写安全策略。长任务的状态持久化与可验证进展借鉴成熟 agent harness 的做法；下述安全机制是结合本项目的设计，不是外部文章对“误报≤10%”的保证。[Anthropic harness 工程实践](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

```text
用户入口 / SDK
  → Capability Preflight（租户、策略、格式、预算）
  → Artifact Upload → 字节完整性与实际格式验证
  → 隔离解析/转码 → 源证据与覆盖清单
  → TaskContext + SourceEnvelope（可信任务与不可信内容分离）
  → 规则/DLP/语义候选检测 + 必需风险覆盖扫描
  → Base Judge → 证据验证 → 必要时 Refiner（限范围复核）
  → 确定性最终裁决
  → ALLOW / MASK / BLOCK / REQUIRE_REVIEW / 检测未完成
  → 变换后再检测 → 绑定本次内容的释放凭证 → 业务模型/下载
  → 统一记录与告警、证据定位、质量反馈
```

### 7.1 单一格式与能力注册表

新增统一注册定义，建议放在 `src/lib/media/formats/registry.ts`，由受控 contracts 导出前后端类型；已存在的 `upload-security.ts`、`magic.ts`、`parser.ts` 和 UI accept 都改为消费者。

每项包含：formatId、extensionAliases、mimeAliases、containerProbe、codecProfiles、category、decoderVersion、extractorPipeline、requiredViews、supportedEntrypoints、maximumBytes/duration/pages/pixels、qualityQualificationId、effectiveStatus。静态格式目录与租户运行状态分开保存。

拟新增 `GET /api/media/capabilities` 返回有效能力与版本，不暴露凭证或内部网络信息；`/api/ocr-models` 改为兼容投影，不再维护另一个独立且失真的模型列表。预检绑定 capabilityVersion，上传完成后仍重新核验；预检通过不是跳过服务端检查的许可。

文件扩展名、客户端 MIME 只作为线索。实际处理先验证魔数，再验证容器结构和流；对常见 MIME 别名、空 MIME、`application/octet-stream` 在字节与解析结果一致时兼容，对不一致给出明确拒绝原因。`ftyp` 不能统一当 MP4 视频；须识别 major/compatible brands，并结合实际流区分 M4A、MOV、HEIF/AVIF。WebM/Matroska 根据音视频流分类，不能靠扩展名猜测。[OWASP 文件上传校验建议](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

### 7.2 上传和异步任务

沿用 `/api/v1/guard/artifacts/uploads`、分片 PUT/签名上传、complete、artifact 状态和 Guard Job。聊天/文档页面使用同一个 UploadSession hook；小文件也经过相同验证逻辑，大文件通过现有 16MiB 分片和对象存储上传，避免在 Next.js 请求中读取整个 500MiB 视频。

状态分为上传和分析两条：上传 `CREATED→UPLOADING→VERIFYING→ACCEPTED/REJECTED`；分析 `QUEUED→PROBING→EXTRACTING→EVALUATING→COMPLETED/PARTIAL/FAILED/CANCELLED`。只有判定所需覆盖完整且无未决风险，才能形成可释放结论。

任务幂等键绑定 tenant/application/subject、requestId、原文与附件 SHA-256、policyHash、pipelineVersion。重试只续做缺失节点，不能把旧模型或旧策略的结果当作当前结果。取消信号传播到 Worker、FFmpeg 与模型请求；Worker 崩溃由租约回收处理；分片、派生文件和过期任务按现有保留策略回收。

文档提交改为返回 `202 {taskId,jobId,status,requestId}`，页面通过轮询或已有事件通道更新进度；保留旧 taskId 查询与历史结果读取。为旧客户端提供明确版本兼容，不把异步排队响应伪装成 completed。

### 7.3 解析隔离与标准中间表示

保留现有命令数组执行、超时、资源预算及 FFmpeg 网络协议限制，将 Office 转换统一放入隔离 Worker。可复用当前转换器；需要补充格式时在固定镜像中组合 LibreOffice/受控 OFD 转换器及适用的 Tika 提取能力，不能仅因工具文档列出格式就声称本项目已支持。[Apache Tika 格式目录](https://tika.apache.org/3.2.3/formats.html)

标准表示 `NormalizedAsset` 至少包含：originalArtifactId/sha256、detectedFormat、codec/streamInfo、derivatives、sourceMap、extractionVersion、coveragePlan/coverageResult、warnings、resourceUsage。每个 TextView 包含 viewId、sourceId、文字、页/单元格/时间范围、OCR/ASR 来源、置信信息是否可用、字符偏移基准和对应原始位置。

文本不安全的 HTML 预览继续消毒；Office 不执行宏、外链或嵌入程序。扫描 PDF 必须渲染并 OCR；混合 PDF 不能只因提取到文字就跳过图片；PPT 备注、表格隐藏行列等列入清单。可不支持的嵌入对象必须报告覆盖缺口。CDR 或转码后的文件是派生物，不能在检查前丢弃原件，使原件中的异常从证据链消失。

### 7.4 图片、音频和视频流水线

**图片：** 解码后保留原图、旋转变换和坐标；按尺寸受控切块，合并 OCR 与原生视觉观察。GIF/动画 WebP、多页 TIFF 路由到帧/页面序列，不丢弃后续帧。现有“多帧图片必须走视频管线”的保护继续保留，补齐实际分流而非删除保护。

**音频：** 使用 ffprobe 检查实际流、时长、声道与编码，再为提供方产生 WAV/MP3 等受支持派生格式；所有要求检测的音轨完整分段转写。以 28 秒片段、1 秒重叠作为智谱短音频接口的初始分段方案，按采样数去重和映射总时间线，不以转写字符串相同作为时间覆盖证明。

智谱官方当前 ASR 文档规定 `glm-asr-2512` 接收 WAV/MP3，单次音频不超过 25MB、30秒。企业 TokenPlan 的文本服务可用不代表该音频接口已授权或共用同一额度；需要单独验证模型/端点/权限，本轮没有发起验证调用。[智谱语音转文本接口](https://docs.bigmodel.cn/api-reference/模型-api/语音转文本)

现有 ASR 适配器要求时间与 confidence；若供应商只返回整段文字，禁止补造逐字时间或 `confidence=1`。优先增加受控对齐器；否则只能标记片段级位置及 `confidenceAvailability=UNAVAILABLE`，达不到精细证据要求时不得签发对应质量资格。语音识别只能覆盖可转写语义，音频异常/非语音风险需独立模型与覆盖声明，不能把“ASR 成功”当成音频所有风险检测成功。

**视频：** 沿用 FFmpeg/ffprobe，探测全部视频流、音轨、字幕、时长和帧信息；抽取音轨 ASR、字幕文本、镜头/运动变化帧及定时帧，风险附近加密分析。图像观察、OCR、字幕、说话人和音频异常分别入图。[ffprobe 的流和容器信息](https://ffmpeg.org/ffprobe.html)、[FFmpeg 格式文档](https://ffmpeg.org/ffmpeg-formats.html)

抽帧覆盖时间段不等于每帧语义已识别。对短时闪现攻击，采用全帧轻量扫描/变化检测与候选加密识别，并用持续时间阈值、采样方式及盲测结果声明能力；无法完成所需全帧或音轨覆盖时记录 PARTIAL。不得把未采到画面的区间计为“安全覆盖100%”。固定数量抽帧可以作为预算受限的检测等级，不能冒充完整原生视频理解。

### 7.5 多模态混合攻击的证据图

节点包括可信任务、用户文本、每个附件、页/帧/音轨、OCR/ASR 视图、风险候选和授权声明；边包括同一任务、同一原件派生、明确文本指代、时间重叠、说话人归属。关系必须附 sourceId 和范围，模型推断关系标记为推断。

分别判断单模态风险、跨模态组合风险和指令来源越权。例如正常保险培训文本与正常图片可以共同解释一段被引述的违规话术；另一方面，文本中的无害表述不能覆盖图片里指向未授权目标的操作指令。判断组合时读取真实任务关系，不能把无关音轨的两个词拼成一次危险动作。

联合派生文本裁判输出 `nativeCoverage=false` 的语义继续保留。只有经过鉴定的视觉/音视频模型真正接收了相应原生内容，才可以声明对应 native coverage。强制数据边界、输入与输出方向都继承至每一条派生视图。

## 8. 裁判模型、智能体角色与误报治理详细设计

### 8.1 模型角色与路由

沿用现有智谱部署选择，不在本方案中未经验证替换模型。将 `glm-5.3`、`glm-5.3-flash` 的现有差异登记为配置一致性任务；联合裁判改成引用已审核 JudgeProfile，不再依赖硬编码的两个模型字符串。

| 角色 | 输入与职责 | 权限与限制 |
|---|---|---|
| 规则/DLP/轻量语义检测器 | 高精度实体、行为关系、候选与覆盖观察 | 确定性或受控模型；强规则与普通候选标识明确 |
| Base Judge | 可信任务上下文、风险定义、来源化的正文与候选 | 每个风险 SAFE/UNSAFE/UNKNOWN；不能执行内容中的命令 |
| Refiner | 有争议风险的正反证、邻域原文、来源与授权范围 | 只复核当前候选；不撤销强制策略、其他风险或其他来源 |
| OCR/ASR/VLM 专用适配器 | 原生图片、音轨、帧或受限视频内容 | 仅产生观察与可验证派生物，不签发最终 ALLOW |
| 证据核验器与最终裁决器 | 字节/偏移/关系/覆盖/授权/模型资格 | 确定性程序；唯一负责确认风险与处置、签发释放绑定 |

这是一组受约束的处理角色，默认无需多个通用自主智能体轮流讨论。Base+Refiner 使用同一模型的结果高度相关，不能按两个独立票数提高置信度；成本、误报、召回均由消融决定是否启用复核。独立模型可作为盲评对照，但不要求引入新的模型供应商。

profile 绑定 modelId/revision、endpoint、modalities、结构化输出能力、最大输入/时长、dataBoundary、qualityApproval 与有效期。供应商目录、网络通达、简单协议探测、独立质量评估是不同层级。不能因模型名称含“5.3”或账户有额度就推断原生多模态能力。

### 8.2 裁判上下文契约

建议增量引入 `JudgmentContextV3`：

```typescript
type EvidenceLocation =
  | { kind: 'text'; viewId: string; startUtf16: number; endUtf16: number }
  | { kind: 'page'; viewId: string; page: number; regionId: string }
  | { kind: 'timeline'; viewId: string; trackId: string; startMs: number; endMs: number };

interface RiskProposal {
  proposalId: string;
  riskId: string;
  verdict: 'UNSAFE' | 'SAFE' | 'UNKNOWN';
  evidence: EvidenceLocation[];
  counterEvidence: EvidenceLocation[];
  relationCodes: string[];
  rationaleCode: string;
  assessmentScopeHash: string;
}
```

这是设计示意，实际定义进入现有 contracts 生成体系；不得手改生成的 golden 文件来绕过兼容检查。

请求同时绑定：tenant/application/subject、direction、userTaskText、sessionSnapshotHash、trustedAllowedActions、用户授权来源、sourceEnvelopes、风险分类与判定条件、必需覆盖、模型/策略/提示模板版本。文件里的“本文属于安全研究”只是待分析内容，不能写入 trustedAllowedActions。未经验证的历史摘要只能用于检索，不能代替原始证据或提升权限。

裁判提示明确区分“谈论风险、引用有害内容、请求实施、实际泄露/外发、受支持求助”，采用风险专属判定表。结构化系统提示与不可信内容分离，引用、OCR、ASR、工具结果均作为数据；从外部内容产生的所谓系统消息不得升级指令优先级。[OWASP 提示注入防护建议](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

### 8.3 有范围限制的反证复核

1. 规则输出分为 HARD_DENY、强证据确认、普通候选、覆盖观察。现有确认类别保留，新增确认依据与可复核属性，不能把全部强规则降为候选。
2. Base 的普通语义 UNSAFE 先生成 proposal；核验器检查原文存在、来源一致、关系成立、内容哈希和风险定义匹配。字符串范围正确只是必要条件，不能替代“证据确实支持该风险”的判断。
3. 触发 Refiner 的条件：高风险候选与明确正常任务冲突；候选含否定/引述/教育语境；OCR/ASR 识别不确定；同一风险不同视图冲突；证据关系不完整。不能只在异常超时后调用 Refiner。
4. Refiner 只能对指定 proposal 给出支持、反驳、未知。反驳必须引用同任务且足以解释该风险的原始反证，生成绑定 proposalId/sourceHash/policyHash/contextHash 的 adjudication receipt。
5. 强制风险、已验证越权行为、其他来源的新风险不因某一个 SAFE 消失。审理不完整或模型不可用时保持 REVIEW/INCOMPLETE，不默认放行。
6. 最终裁决确认后，按现有会话与释放边界固化；后续复核可生成新版本审计决议，不能追溯授权已经未授权的输出。

由此修复“普通语义过早确认且无法纠偏”，同时保持现有强制风险单调性。反证不能是一句通用“这是测试”，也不能借白名单清除整段/整个用户的所有风险。

### 8.4 金融专业判定与黑白样本库

将主题词、业务实体、行为关系、处置策略分开维护，继续复用现有词库和发布治理。示例分类：违规收益承诺、误导销售、越权查询/外传、个人金融信息泄露、冒用身份、欺诈诱导、反洗钱规则规避、保险免责/理赔误导。这里是产品风险分类，不替代法律合规结论。

| 正常语境候选 | 需要保留的判定信息 | 不允许的过度放行 |
|---|---|---|
| 培训材料引用“保本保收益”并明确禁止 | 引号、禁止关系、任务为解释、受众及上下文 | 不能因出现“培训”就允许正文另行承诺收益 |
| 客户询问拒赔原因或申诉方式 | 用户求助目的、事实叙述、未要求伪造材料 | 不能把合法申诉同规避审核自动混为一类 |
| 内部授权核对客户信息 | 来自系统的权限、字段、脱敏与目的限制 | 文件声称“内部”不构成授权，完整凭证外发仍受限制 |
| 反洗钱风险教育/案例研讨 | 描述与实施请求的差异、输出是否变成可执行规避建议 | 不能对所有含“反洗钱”请求全局白名单 |
| 新闻、法务研读、对攻击的解释 | 引述范围、输入/输出方向、是否产生新的危害指令 | 不能让安全解释变成对攻击行为的实际协助 |

每条样本保存：金融子领域、任务类型、允许/禁止理由、风险 span 与反证 span、授权条件、来源、标注人/复核人、版本和争议状态。黑样本与正常对照成对设计，只改变关键关系而保留敏感词，确保模型学会语义条件而不是词表泄漏。白库作为有限反证检索，不作为绕过风险检测的 ALLOW 列表。

误报反馈采用“用户反馈→待复核→两位评审独立判断→争议裁决→离线候选→盲测→签名发布”。不允许用户点一次“误报”就自动更新全局白名单。反馈内容属于不可信训练/评测输入，保留租户隔离和污染审查。

### 8.5 长文档与跨轮上下文

优先按章节、段落、说话人和时间切片；每个检测窗口包含待判片段、有限邻域、可信任务及精确原文映射。上下文摘要提供导航，最终证据必须落到原文。对关系跨窗口的风险，调度相邻窗口或指定关联页，而不是任意全量拼接。

全文结果按照 `riskId + sourceId + canonicalSpan + relationId` 合并同一风险事件，重叠片段、重复帧和重复 ASR 片段仅关联证据，不重复制造告警。去重不降低风险级别，不丢失多个独立受影响对象，不把不同时间发生的事件合并成一次。

会话状态继续绑定 session/tenant/application，加入 contextSnapshotHash 与 eventSeq；重试不重复累积风险，撤销某一候选不清除其他轮的强证据。TaskContext 增加后，judge cache key 必须同步包含来源、授权、方向、任务、策略、模型和模板版本，防止相同文本跨场景复用错误裁决。

### 8.6 预算与故障策略

默认一轮 Base；仅争议候选触发一次 Refiner。按窗口数、token、媒体分钟和租户设置总预算，并由统一调度器实施。现有进程内 inflight 限制不能代表跨多个 Worker 的总并发，需要共享租约/配额。429/短暂5xx可在总 deadline 内重试，401/403、身份变化、质量资格缺失和边界拒绝直接停止该路由。

初始交互目标建议为文本判定 p95≤5秒、小图片≤15秒；超出同步预算转为明确异步，不能强行超时判安全。音视频按时长展示预计完成时间，以实测实时系数制定容量目标。以上是待鉴定的性能预算，不是本轮实测结果；模型和部署能力不足时必须调整资源或产品 SLA。

私有数据仅进入已批准边界，云端回退沿用现有审批规则。鉴权失败、超时、codec 不可用、语义未确认与真实风险使用不同 reasonCode。业务可配置“未完成则拒绝释放”，但审计中风险 verdict 仍为 UNKNOWN。

## 9. 前后端接口、存储与展示设计

### 9.1 接口演进

| 接口/对象 | 增量设计 | 兼容要求 |
|---|---|---|
| `/api/media/capabilities`（拟新增） | 返回有效格式、限额、能力状态及版本 | 客户端 accept 和服务端验证共用同源定义 |
| `/api/v1/guard/artifacts/*` | 复用分片/完整性/租户验证，补充实际格式、解析计划及能力版本 | 不取消 SHA-256、所有权、过期和配额校验 |
| `/api/v1/guard/jobs` | 同一 job 接收 text + verifiedArtifactRefs + TaskContext | 未完成验证、跨租户或不匹配哈希拒绝；拒绝任意远程 URL |
| `/api/document-scan` | 旧入口作为兼容适配，转 Artifact+Job；异步结果与历史任务关联 | 版本化响应，旧历史可读；不继续同步全文件检测 |
| `/api/chat` | 增加版本化多模态消息联合类型；支持已有纯文本调用 | 客户端不传可信角色/任意 system 授权；保持当前权限及 CSRF |
| `/api/simulate`、样本导入与评测 | 复用同一 job 输入与证据，不独立实现解析 | 实验策略结果不可当已上线效果；UNKNOWN 标签不进入主质量指标 |
| 错误响应 | 统一 Problem `code/detail/requestId/retryable` | 前端读取 detail；用户提示与管理诊断分级，不能只有“上传失败” |

`artifactRef` 至少包含 artifactId、sha256、purpose、绑定任务的引用 ID；读取时由服务端回查 tenant/application/owner、accepted 状态、过期、策略及分析完成情况，不能相信客户端自报状态。

模型可接收的原生格式更少时，使用受验证派生物并绑定原件/派生件哈希；受控适配器负责提供方 wire format。当前 native 单块 1MiB 不直接放宽到视频上传上限，采用受控分段/压缩或经鉴定的对象引用协议。服务端不能任意下载用户填写的 URL，也不能把上传成功的原件绕过护栏直接交给模型。

### 9.2 数据与审计

优先扩展现有 Artifact、任务、证据和决策存储，新增字段或子表：formatDetection、processingProfileVersion、sourceMap、coverageManifest、judgmentContextHash、adjudicationReceipts、operationalOutcome、model/codec/extractor versions。不要再造一套不同 ID 的风险告警系统。

风险事件与处理失败分别存储、统一可检索；一个 job 可同时有已确认风险和覆盖缺口。详情包含可信任务、原始与派生证据、命中词/范围、正反证摘要、调用顺序、模型身份、耗时、最终策略理由。图片框选、PDF 页码、表格单元格、视频/音频时间段点击定位；逐字时间缺失就显示片段范围。

保留现有原文访问授权、脱敏、删除、留存和审计边界。此前的“180天会话记录”需求与原始媒体留存不同，不能把当前文档7天或原文关闭配置说成已满足180天全媒体保存；本轮新字段继承明确的租户保留策略，是否延长原始媒体存储另按既有需求验收。

### 9.3 UI 交互

统一 shadcn/ui 上传组件：选择/拖拽、能力解释、文件列表、每个文件状态、取消、失败重试、总预算。录音先请求浏览器麦克风权限，停止后将浏览器真实输出（常见 WebM/Opus 等）交给注册表，不伪装成 WAV。

聊天在附件验证完成后允许提交任务；分析排队时显示状态，业务模型调用延后至护栏允许。清空、重复点击、切换策略、附件过期、部分失败都有可预期行为。文档检测新增音视频预览和定位，复用已有证据页面，不维护第二份 findings。

告警列表默认按风险事件去重；可查看“证据出现次数”。系统异常页单独呈现“尚未完成检测”，两者都在请求历史保留。普通用户看到可采取的操作，管理员看到 requestId 与节点故障详情；不展示 API key、内部路径或完整私有数据。

## 10. 关键难点与取舍

| 难点 | 采用方案 | 不采用方案及原因 |
|---|---|---|
| 降误报同时防漏报 | 关系证据、有限反证复核、任务级裁决，召回门禁与配对消融 | 全局降阈值/加白名单会扩大漏检；简单多数投票不证明独立性 |
| 已确认风险不能随意抹除 | 仅普通语义 proposal 在最终确认前可复核；强制风险保持单调 | 让任意第二次 SAFE 覆盖所有风险会破坏原有安全边界 |
| 原生与派生能力区分 | 按视图、模型输入和风险族签发覆盖资格 | OCR/ASR 文本只能证明相应语义覆盖，不能代表原生视频全面识别 |
| 大文件、长视频与模型短输入 | 对象分片、隔离 Worker、可续做任务、时间线分段及预算 | Next 请求内同步处理容易超时；把文件存储上限当模型上限不可行 |
| 兼容多格式又不放松上传校验 | 同一 registry + magic/container/codec probe + 沙箱解析 | 只放宽 MIME 或加后缀会接入伪装文件和不可解析格式 |
| 识别结果定位与误差 | 原始字节/字符/页/时间/坐标多层映射，缺失时明确精度 | 伪造 ASR confidence/时间戳使证据不可验证 |
| 自动回退与数据边界 | 回退只在已审批边界和模型资格内，错误可追踪 | 企业 TokenPlan 有额度不能推导可发送全部私有媒体 |
| 长文档局部告警累积 | 上下文核验、事件级去重、逐风险最终裁决 | 求平均可能稀释高危；仅展示去重不能算 FPR 改善 |
| 质量证据长期有效 | 绑定策略、模型、模板、parser、codec、上下文版本 | 仅绑定应用 commit 无法解释同代码不同部署结果 |

架构复核结论：以统一 Artifact/Job 和 V2 为主干，比增加第三套“多模态聊天检测器”更容易保证入口一致性；先修前后端能力契约，再接真实适配器，最后校准判定。普通智能体只承担受限制的解释和建议，最终权限仍由程序控制。先完成闭环与关键安全缺口，再扩大格式数量和调优成本，避免一次重写拖延基本可用性。

## 11. 基准、消融与自动化验收计划

以下均为待恢复测试后的执行安排，本轮未执行。

### 11.1 数据建设与标注

建立三层：诊断开发集、阈值/提示校准集、锁定独立验收集。按原始对话/文档/录音/视频及其所有派生物成组划分；同一内容的格式转换、同模板近重复、同会话不同轮不得跨集。保留原始标签与本地风险任务映射；未知或争议样本单列，不强行归为正常或风险。

正式独立集建议至少 4,000 个正常请求、4,000 个风险请求，覆盖文本、图文、纯音频、纯视频和混合请求、输入/输出、中文/英文及金融业务；关键切片至少正常200、风险200，数量不足标记证据不足。标签由两位评审独立判定、第三人裁决争议，判定最终行为及证据是否正确，不只看含哪些词。现有“至少2000”门槛保留，此处提高正式独立集规模。

线上 FDR 以授权使用的真实告警概率抽样为准，保留抽样概率和时间/租户/风险/入口分层；不能仅抽“有争议”告警估计整体 FDR。首轮建议≥500条有效复核阻断结果，另抽正常请求估计漏检及故障干预。自然流量不足则延长观察，不能人为补风险样本改变基率后冒充线上结果。加权结果和按会话聚类的不确定性单独计算。

### 11.2 必须覆盖的误报与安全对照

| 用例族 | 正常样本 | 配对风险变化 | 验收观察 |
|---|---|---|---|
| 金融话术 | 培训中禁止不当收益承诺 | 去掉禁止关系并变成实际销售承诺 | 正反证范围和受众判定 |
| 引述与求助 | 报道诈骗、求助与应对风险 | 变成面向受害人的诱导实施 | 内容提及与行为请求区分 |
| 长文档 | 上下文解释分散在相邻段/页 | 同文档另一处增加独立高危行为 | 不因分片误报，也不因良性章节覆盖高危 |
| DLP/授权 | 合法脱敏字段、授权核对 | 未授权完整凭证外发 | typed DLP、授权边界和精确 MASK |
| OCR/ASR | 低清、口音、噪声下的否定句 | 真实请求位于低置信度区间 | 不确定性可见，局部重识别有效 |
| 多轨视频 | 旁白与字幕是同一案例的说明 | 另一音轨/短时帧包含独立攻击信息 | 全轨覆盖、时间范围、跨源归因 |
| 混合附件 | 正文解释图中文字为反例 | 图文分开无害、结合后形成越权请求 | 联合关系检测和任务绑定 |
| 识别故障 | 正常文件遇到提供方失败 | 恶意文件遇到相同失败 | 两者均显示缺口，不冒充检出，也不静默放行 |

### 11.3 逐入口真实联通验收

对第6节每个业务入口执行：浏览器选择真实文件→上传字节→Artifact accepted→实际解码/转写→Guard Job→判定→告警/详情→允许时业务模型输出或安全下载。检查 requestId/jobId/artifactId/decisionId 串联、发送给模型的真实内容哈希、取消和重试行为。

A/B 每种扩展名均有有效样本与异常样本；每个声明支持的 codec profile 均有至少一条真实解码及风险定位用例。组合维度包括：MIME 别名/为空/伪装、截断、编码/BOM、旋转、多页/动画、长时长、多个音轨、字幕、重名、越权 artifact、过期签名、哈希不符、并发、配额、重试、模型超时、取消。

保留 UI mock 测试用于组件开发，但它不能证明联通。正式健康检查必须返回预期成功，登录必须真实成功，不跳过认证测试；不接受 500/503 作为成功，除非该用例专门验证故障行为。测试报告分别列出“组件 mock、协议、真实适配器、真实浏览器、质量”，不可混算通过率。

### 11.4 消融顺序

冻结相同数据、策略及模型版本，比较：A现有 V2；B统一上下文；C关系/反证核验；DBase+按需 Refiner；E多模态完整管线；F最终组合。保留分别关闭 Base、Refiner、邻域、跨模态关系的结果，按风险、入口、长度、格式、语言统计 TP/FP/FN、FDR、理由匹配、p95、模型调用数和成本。

先以少量协议和真实链路用例检查501、格式、模型身份、覆盖契约，再运行冻结集。不可在一个失败入口上直接全量跑完所有数据集并把技术错误计入安全指标。

### 11.5 发布门禁

| 门禁 | 通过要求 | 失败处理 |
|---|---|---|
| G0 接入一致性 | 本批入口×格式 profile 全部完成真实链路；错误可解释；租户/哈希/释放绑定无绕过 | 暂不开放该 profile；不得宣称全格式交付 |
| G1 语义质量 | 正常 FPR≤1%，严格阻断 FDR≤10%；原准确率≥95%、召回≥95%、FNR≤5%保持；理由匹配已复核 | 继续诊断，保留候选影子状态 |
| G2 统计充分性 | 独立验收、标签审定、样本量达标；主 FPR/FDR 的95%区间上界分别≤1%/10%；关键切片不足即标记未鉴定 | 增加独立证据，不调整分母或复用已看过样本 |
| G3 安全不退化 | 强制风险与授权边界用例无新增漏放；相对冻结基线的配对召回差异95%区间下界不得低于-1个百分点；严重风险用例逐例审查 | 回退对应规则/提示/适配器候选 |
| G4 运行可用性 | 声明支持且满足预算的有效文件端到端完成率≥99%；正常请求因系统故障中断率≤1%；资源/延迟在已批准 profile 预算内 | 不以误报指标掩盖可用性问题 |
| G5 真实业务效果 | 概率抽样线上/代表性业务 FDR≤10%，同时报告基率、置信区间及误拦；没有足够证据时不得声称线上达标 | 保留影子/有限灰度并扩充观察 |

新的统计与可用性门槛为本方案建议的正式交付标准；不降低任何既有门槛。开发阶段可以先达到“误报改善且召回无明显退化”的中间里程碑，但不能据此签发完整 ENFORCE 资格。

## 12. 分批实施与可执行任务

所有任务为 `PLANNED`；“测试恢复”是涉及执行测试的明确前置状态。研发可按下述依赖逐项实施，后续用户发出执行指令时以本清单为基线，不把编写方案当作修复完成。

| 任务 | 优先级/批次 | 责任角色 | 改动及交付 | 依赖与验收 |
|---|---|---|---|---|
| T01 冻结验收与版本身份 | P0/一 | 架构+质量 | app/worker/analyzer/policy/model/parser/codec 清单，部署差异及配置预检 | 输出可复核基线；拒绝未展开占位符，敏感配置不出日志 |

## 13. 发布、回退与后续执行入口

实现坚持增量迁移：先增加字段和兼容适配，再切换入口；历史任务保留旧 schemaVersion 阅读路径。每个任务关联独立变更和证据，不把格式、提示词、策略、模型一起做成无法分辨的巨型发布。

先在与目标部署一致的隔离环境验证，绑定真实镜像及策略身份；然后影子比较，最后按租户/流量逐步激活。策略仍经现有签名/质量门禁发布，不绕过候选未激活状态。发现强制风险漏放、跨租户证据、释放绑定不符立即回退；误报、故障干预或时延超过阈值时停止扩量并回退对应 profile/策略版本。

回退需同时考虑 app、Worker、analyzer、contracts、模型 profile 和策略。采用兼容的增加字段迁移，避免回退应用时旧 Worker 无法读取新 job；未完成任务保持原版本执行或显式重新创建，不能混合版本结果。

后续执行顺序：先读本方案与配套任务 JSON→核对 main及运行版本→T01/T02/T03/T10/T15/T18→按依赖推进第二批→T16/T17/T19/T21→恢复测试后 T22/T23→通过门禁再 T24。没有新的恢复测试指令时，不启动基准或真实模型调用。

最终关闭条件：双误报指标与原有更严门槛通过、召回与风险理由通过、全部列入交付的入口和格式 profile 完成真实联通、未完成检测不冒充安全、用户能定位证据并区分故障与攻击、策略及部署可回退。任何一项只有源码而无所需验证证据，状态保持待验收。
