# 2026 年论文开源实现成熟度与产品集成选型报告 V1.0

> 调研日期：2026-09-03
> 适用产品：AI 安全一体机 / 大模型护栏平台
> 关联报告：`11_与NSF_AI安全一体机白皮书功能性能差距及优化计划_V1.0.md`、`12_2026大模型与Agent安全前沿研究及产品升级路线_V1.0.md`

## 1. 结论先行

本轮核查后的核心结论是：不能把“论文公开了 GitHub”直接等同于“可集成的开源软件”。很多 2026 年论文仓库只有数次提交、没有版本发布、缺少许可证，或者只包含攻击脚本和评测数据。它们适合转化为测试用例，不适合进入产品运行链路，更不能随一体机对外分发。

当前产品最适合采用“稳定基础组件 + 自研安全控制面 + 论文方法转化测试”的组合：

| 优先级 | 推荐组件 | 在产品中的职责 | 推荐结论 |
|---|---|---|---|
| P0 | [Cedar-Java](https://github.com/cedar-policy/cedar-java) | 工具调用、资源访问、Agent 动作的确定性授权 | 直接集成，优先于同时引入 OPA |
| P0 | [Qwen3Guard](https://github.com/QwenLM/Qwen3Guard) | 中文/多语言输入输出语义安全分类 | 先以 Gen 0.6B/4B 影子模式接入，再决定在线阻断 |
| P0 | [Presidio](https://github.com/data-privacy-stack/presidio) | 文本、图像、结构化数据中的 PII 识别与匿名化 | 以独立容器接入，补充中文识别器 |
| P0 | [Promptfoo](https://github.com/promptfoo/promptfoo) | 策略回归、越狱测试、版本发布门禁 | 直接用于离线安全评测，不进入请求热路径 |
| P0 | [garak](https://github.com/NVIDIA/garak) | 广覆盖模型弱点和攻击探针扫描 | 作为第二套独立扫描器，夜间和发版前运行 |
| P0 | [Trivy](https://github.com/aquasecurity/trivy) + [ModelScan](https://github.com/protectai/modelscan) + [YARA-X](https://github.com/VirusTotal/yara-x) | 容器、依赖、模型文件、技能和插件供应链扫描 | 直接进入制品导入、构建和升级门禁 |
| P0/P1 | [MaliciousAgentSkillsBench](https://github.com/protectskills/MaliciousAgentSkillsBench) | Agent 技能恶意样本、规则和动态分析基准 | 数据/规则直接吸收，动态执行器仅在一次性沙箱运行 |
| P1 | [MalSkills](https://github.com/security-pride/MalSkills) | Skill 指令、代码、清单和安装脚本的神经符号分析 | 隔离 POC，借鉴依赖图和跨文件数据流设计 |
| P1 | [NeMo Guardrails](https://github.com/NVIDIA/NeMo-Guardrails) | Retrieval、tool input/output rail 参考实现 | 采用独立 sidecar 做 POC，不替换现有 GuardEngine V2 |
| P1 | [ToolSafe / TS-Guard](https://github.com/MurrayTom/ToolSafe) | Agent 工具调用序列的风险判定 | 仅接入 Apache-2.0 模型权重做对比试验，框架代码暂不集成 |
| P2 | [MUZZLE](https://github.com/gsiros/muzzle) | Web Agent 间接提示注入自适应红队 | 建独立红队实验室，不进入生产环境 |
| P2 | [SafeGuard-VL](https://github.com/adorableChowhound/SafeGuard-VL) | 图像安全策略自适应判定与测试集 | 测试集优先，7B 模型作为 GPU POC |
| 观察 | [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | Agent 运行时、会话和事件适配 | 适合兼容性实验，不应成为安全状态或授权的权威来源 |

不建议现在直接集成 ACE、FragFuse、ObliInjection、Confundo、DTR、MEval、ConjunctiveAgents 等论文仓库。它们的价值主要在攻击算法、数据集和评测方法，应通过内部重写转化为 Promptfoo/garak 的测试用例。

## 2. 评价方法

### 2.1 评分维度

| 维度 | 权重 | 重点检查项 |
|---|---:|---|
| 法律可用性 | 20% | 是否有明确 LICENSE，是否允许商业使用、修改、再分发，模型和数据是否另有条款 |
| 完整性与可复现性 | 20% | 代码、配置、模型/数据、运行步骤是否齐全，论文结果能否复现 |
| 维护与版本治理 | 15% | 是否持续维护，是否有 release、变更日志、版本兼容和安全响应 |
| 工程质量 | 15% | 测试、CI、文档、错误处理、可观察性、固定依赖和制品校验 |
| 私有化部署能力 | 15% | 是否支持容器、离线运行、本地模型/API，是否有未声明遥测或外部依赖 |
| 当前架构适配度 | 15% | 与 Java 网关、TypeScript/Next.js、Docker 和既有 GuardEngine V2 的集成成本 |

成熟度分级：

| 等级 | 分数 | 含义 |
|---|---:|---|
| A | 85-100 | 可进入产品集成，但仍需内部安全评测、版本固定和许可证归档 |
| B | 70-84 | 适合隔离 POC 或非关键链路，达到验收指标后再生产化 |
| C | 50-69 | 只适合作为测试集、红队工具或算法参考 |
| D | 0-49 | 尚未公开、许可不清、代码不完整或与当前产品不适配 |

### 2.2 评分限制

- 星标数量只作为社区采用度的弱信号，不作为安全性证明。
- “代码可见但没有 LICENSE”按不可再分发处理。除非作者补充许可证或书面授权，否则不得复制进商业产品。
- 论文报告的准确率、攻击成功率和延迟不能直接写入产品规格。必须在本产品模型、中文语料、硬件和策略上复测。
- 同一个项目的代码、模型权重、数据集可能采用不同许可证，必须分别归档。
- 任何会执行第三方 MCP、Skill、模型或安装脚本的扫描器，都必须在无生产凭证、无宿主机写权限的一次性环境中运行。

## 4. 非论文基础组件成熟度与选型

论文原型可以提供新方法，但产品主链需要由经过长期维护、许可证清晰、可测试和可回滚的基础组件承载。

### 4.1 在线安全决策组件

#### 4.1.1 Cedar-Java：推荐进入 P0

[Cedar-Java](https://github.com/cedar-policy/cedar-java) 使用 Apache-2.0，提供 Maven 制品、JDK 17+ 支持和集成测试。它可以嵌入 Java 网关，对结构化的 principal、action、resource、context 做确定性授权。上游明确说明 Java 绑定会略晚于 Rust Cedar 新特性，因此必须固定 release 分支和 Maven 版本，不能跟随 `main`。

推荐原因：

- 与当前 Java 网关天然匹配，不需要新增网络 sidecar 才能完成关键授权。
- 策略和实体 schema 可验证，适合工具、MCP、知识库、模型路由和高风险数据访问。
- 可把“允许调用工具”与“模型认为内容安全”彻底分开，防止语义模型单点误判直接触发动作。
- 适合实现 deny-overrides、默认拒绝、职责分离和租户级策略继承。

限制：Cedar 不负责理解自然语言，不应替代 GuardEngine V2 或安全分类模型。策略编译、版本审批、灰度和决策证据仍需自研。

备选是 [OPA](https://github.com/open-policy-agent/opa)。OPA 社区和云原生生态更大，但通常以 Rego 和 sidecar/REST 方式部署。当前产品优先 Cedar-Java，除非目标客户已有统一 OPA/Rego 管理体系。不要在第一阶段同时引入两套策略语言。

#### 4.1.2 Qwen3Guard：推荐进入 P0 影子模式

[Qwen3Guard](https://github.com/QwenLM/Qwen3Guard) 提供 0.6B、4B、8B 的 Gen 和 Stream 变体，覆盖中文及多语言，并可通过 Transformers 或兼容推理服务运行。它比英文优先的传统分类器更适合作为当前产品的中文语义安全候选。

推荐接法：

- 第一阶段仅接 `Qwen3Guard-Gen-0.6B` 和 `4B`，使用统一 OpenAI-compatible 内部推理适配器。
- 输入和输出检测并行或分级执行，低风险走快速模型，高风险或争议类升级到较大模型/人工复核。
- `Stream` 变体先做 POC。其 token 级头与 tokenizer 绑定，不能假设能无缝接入所有上游模型的流式 token。
- 把三分类结果映射为产品内部风险等级和证据，不把模型原始标签直接作为最终 allow/deny。

风险与前置条件：

- 代码仓、每个模型权重和数据/benchmark 的许可证必须逐项核查并归档，不能默认继承 Qwen 其他仓库许可。
- 必须针对中文业务、保险/金融合规、越狱、隐私和正常拒答建立自有金标集。
- 先测 P95/P99 延迟、显存、吞吐和误报，再确定 0.6B、4B 或级联方案。

#### 4.1.3 Presidio：推荐进入 P0/P1

[Presidio](https://github.com/data-privacy-stack/presidio) 使用 MIT，支持文本、图像和结构化数据中的 PII 分析、匿名化和可扩展 recognizer，并提供容器化 REST 服务。项目在 2026 年转向社区治理，仍维持 MIT 和持续发布。

推荐接法：

- 作为独立 DLP sidecar，放在现有 API 网关后方，不直接暴露到不可信网络。官方文档明确指出其 REST 服务不自带认证授权。
- 保留现有确定性身份证、手机号、银行卡、密钥规则；用 Presidio 承担 NER、上下文增强和图像 OCR 后的实体识别。
- 新增中国身份证、统一社会信用代码、保单号、客户号、车架号和企业自定义词典 recognizer。
- 返回实体类型、区间、置信度和识别器来源，由产品统一完成遮蔽、阻断、审计和可逆令牌化。

#### 4.1.4 NeMo Guardrails：成熟，但只做选择性吸收

[NeMo Guardrails](https://github.com/NVIDIA-NeMo/Guardrails) 有长期维护、测试、文档和发行版，支持 input/output、retrieval、tool input/tool output 和 streaming rails。它适合快速验证 RAG 和工具 rail 的编排，但与现有 GuardEngine V2 存在明显功能重叠，而且引入 Python/Colang 运行时。

推荐范围：

- 只做独立 sidecar POC，重点验证 retrieval rail 和 tool rail。
- 不替换现有 Java streaming commit gate、租户策略和审计控制面。
- 私有化一体机必须显式关闭并验证匿名使用统计，例如项目文档提供的 `NEMO_GUARDRAILS_NO_USAGE_STATS=1` 或 `DO_NOT_TRACK=1`，并通过出网审计确认。

### 4.2 安全评测与红队组件

| 组件 | 成熟度 | 推荐定位 | 关键限制 |
|---|---:|---|---|
| [Promptfoo](https://github.com/promptfoo/promptfoo) | A, 91 | 主评测编排器，管理策略回归、攻击集、provider、阈值和报告 | Node 版本要求较新；按本项目规范通过 pnpm 或固定容器使用，不进入在线请求链路 |
| [garak](https://github.com/NVIDIA/garak) | A-, 88 | 独立 LLM 漏洞扫描器，补足 Promptfoo 未覆盖的探针族 | Python 环境独立；攻击运行需限额，避免对生产模型造成成本和内容污染 |
| [PyRIT](https://github.com/Azure/PyRIT) | B+, 82 | 第二阶段的自适应、多轮和目标驱动红队 | 较重，和 Promptfoo/garak 有重叠；不应在 P0 同时铺开 |
| [MUZZLE](https://github.com/gsiros/muzzle) | B, 74 | Web Agent 间接提示注入专项实验室 | 环境复杂，会运行浏览器 Agent 和模拟应用；必须使用隔离网络和可重置数据 |
| [Confundo](https://github.com/HKU-TASR/Confundo) | C, 64 | RAG 投毒专项攻击生成 | 是攻击研究工具，不是防护组件；禁止连接生产知识库 |

推荐分工：Promptfoo 负责产品版本化用例和发布门禁，garak 负责广覆盖模型扫描，MUZZLE/Confundo 负责季度专项红队。只有当多轮自适应攻击成为明确需求时再引入 PyRIT。

### 4.3 模型、容器、Skill 和 MCP 供应链

#### 4.3.1 ModelScan

[ModelScan](https://github.com/protectai/modelscan) 使用 Apache-2.0，专门在不反序列化执行模型的前提下发现 Pickle、H5、SavedModel 等格式中的危险内容。它适合放在模型上传、同步和部署之前。

边界必须写清：ModelScan 主要解决危险序列化和嵌入代码，不解决模型后门、恶意训练数据、safetensors 内容语义风险或许可证问题。还需要 SHA-256、签名、来源 allowlist、SBOM、模型卡和离线行为测试。

#### 4.3.2 Trivy

[Trivy](https://github.com/aquasecurity/trivy) 可扫描镜像、文件系统、依赖、IaC、secret、license 和 SBOM，适合作为构建和升级包门禁。

必须加入特殊控制：Trivy 项目披露 2026-03-19 发生过发布凭证被盗和恶意 `v0.69.4` 制品事件。因此“成熟项目”不等于“下载 latest 即可信”。一体机应使用内部镜像仓、版本 allowlist、官方校验值/签名、双人升级审批和已验证漏洞数据库快照，禁止使用该受影响版本。

#### 4.3.3 YARA-X

[YARA-X](https://github.com/VirusTotal/yara-x) 使用 BSD-3-Clause，官方说明已经在 VirusTotal 生产环境扫描数十亿文件和数万条规则，适合做 Skill、插件、模型配套脚本、压缩包和安装器的静态签名扫描。

推荐把 MaliciousAgentSkillsBench/MalSkills 中确认的恶意行为转化为内部 YARA-X 和 Semgrep 规则包，但需要人工去重和误报评估。YARA-X 是高性能预筛器，不是最终信任判定。

#### 4.3.4 Snyk Agent Scan

[Snyk Agent Scan](https://github.com/snyk/agent-scan) 使用 Apache-2.0，能发现 MCP、Agent 和 Skill 中的提示注入、工具投毒、工具遮蔽、有害流、凭证处理和恶意载荷，功能很贴合当前产品方向。

暂不推荐作为一体机核心依赖，原因包括：

- 分析流程依赖 Snyk token/API，私有化和离线交付存在约束。
- 文档说明 JSON/issue 输出仍可能变化，不适合作为稳定产品合同。
- 大规模使用其标准 API 受限制。
- 扫描 MCP 配置会实际执行其中定义的命令，错误使用会把扫描器变成执行入口。

建议只在无敏感数据的一次性 VM 中做 POC，用于校验本产品自研 MCP/Skill 扫描器的覆盖率，并吸收其风险分类思想。

### 4.4 DeepSeek Harness 适配结论

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 使用 MIT，采用 TypeScript、pnpm monorepo、插件化架构，包含 session persistence、sandbox、UI、自动化接口和较完整的开发门禁，从技术栈上与当前 Next.js/TypeScript 产品接近。

它目前明确处于 developer preview，并声明会发生兼容性破坏。因此建议定位为：

- Agent 兼容性测试入口。
- 会话和工具事件的一个数据源。
- 研究 Agent 运行时、插件生态和沙箱接口的参考实现。
- 产品演示或开发者实验环境，而不是一体机的权威安全控制面。

不能把 Harness 的会话存储直接当成“安全会话记忆”。安全相关状态必须继续由产品控制：租户、主体、策略版本、风险累计、数据来源、工具批准、序列号、过期时间、加密和审计证据均需由网关/安全服务管理。Harness 发出的事件应经过 schema 校验、租户绑定、重放保护和签名验证后才能参与决策。

推荐事件合同至少包含：

```text
tenant_id, principal_id, application_id, session_id, turn_id,
actor, source_type, source_id, tool_name, args_digest,
content_digest, provenance, risk_labels, event_seq,
created_at, expires_at, signature
```

结论：适合 B 级隔离 POC，不适合替换现有 GuardEngine V2、GatewayRateLimiter、StreamingCommitGate、策略数据库或审计链。

## 5. 推荐目标架构

```text
                    管理面 / Next.js
       策略版本、模型版本、例外审批、证据、评测报告
                              |
                              v
请求 -> Java Gateway -> 现有 GuardEngine V2 -> 风险聚合器 -> 上游模型/Agent
          |                 |        |
          |                 |        +-> Qwen3Guard Gen sidecar
          |                 +----------> Presidio DLP sidecar
          +-> Cedar-Java Action PDP
              principal + action + resource + context
                              |
                              v
                      Tool / MCP / RAG PEP

离线评测面：Promptfoo + garak + MUZZLE + 论文攻击语料
供应链面：Trivy + ModelScan + YARA-X + Semgrep/MalSkills 规则
运行时来源：自有 Agent 或 DeepSeek Harness adapter，仅发送受验证事件
```

关键原则：

1. Cedar 处理“是否允许执行”，语义模型处理“内容/上下文是否危险”，两者不能互相替代。
2. 任何模型分类结果都由风险聚合器映射为统一内部 schema，不让第三方标签侵入核心策略。
3. 攻击框架、动态 Skill/MCP 扫描器和浏览器 Agent 永不进入生产数据平面。
4. 外部组件通过 adapter 接入，支持超时、熔断、降级和一键移除；高风险动作不能在组件失败时默认放行。
5. 一体机所有模型、容器、规则库和漏洞数据库都使用固定版本、哈希、签名和本地镜像。

## 6. 分阶段集成计划

### P0：0-30 天，建立可控基础

1. 建立第三方制品台账：代码许可证、模型许可证、数据许可证、版本、commit、SHA-256、来源、NOTICE、CVE 和维护人。
2. 定义统一 `SecurityDecision` 合同：`decision`、`risk_level`、`categories`、`evidence`、`policy_version`、`model_version`、`latency_ms`、`fail_mode`。
3. 以 Promptfoo 建立安全回归工程，把当前规则测试、ACE/FragFuse/ObliInjection/ToolHijacker/MEval 的方法转为自有用例，不复制无许可证源码。
4. 加入 garak 夜间扫描和发版前扫描，与 Promptfoo 结果分别保留，避免同一检测器既生成又判定。
5. 在构建和导入链加入 Trivy、ModelScan、YARA-X；建立禁止 `latest`、禁止未签名制品、禁止危险序列化格式的策略。
6. 引入 MaliciousAgentSkillsBench 的可许可样本和规则，建立 Skill/MCP 静态扫描基线。
7. 部署 Qwen3Guard-Gen 0.6B/4B 影子服务，不阻断流量，只记录与现有 GuardEngine V2 的一致、互补和冲突结果。

交付物：组件 SBOM、许可证清单、固定镜像、统一决策 schema、首版中文金标集、基线准确率和性能报告。

### P1：31-60 天，形成在线纵深防护

1. 在 Java 网关嵌入固定版本 Cedar-Java，定义 principal/action/resource/context schema。
2. 首批纳管高风险动作：外发消息、上传/下载文件、执行代码、调用支付/工单/数据库、读取敏感知识库、修改 Agent/Skill/MCP 配置。
3. 接入 Presidio sidecar，完成中国 PII、保险/金融实体和企业自定义 recognizer；与现有规则做并集、冲突和置信度策略。
4. 根据 P0 数据选择 Qwen3Guard 规格和级联方式，先从高风险租户/应用灰度，不全量替换现有规则。
5. POC MalSkills 的跨文件 Skill Dependency Graph。验证其对中文 `SKILL.md`、PowerShell、Shell、TypeScript、Python 和 Java 的覆盖。
6. 对 NeMo Guardrails 只验证 retrieval/tool rail，并测试完全离线、遥测关闭和故障行为。

交付物：Action Firewall、PII/DLP sidecar、语义分类灰度、MCP/Skill Registry、失败模式矩阵和可回滚版本。

### P2：61-90 天，增强 Agent 与多模态防护

1. 将 TS-Guard 8B 作为隔离服务，与 Qwen3Guard、现有规则在工具调用序列上 A/B 对比；不引入无许可证 ToolSafe 框架代码。
2. 用 SafeEditBench 和 UnsafeBench 评测现有视觉审核；只有在新增覆盖显著且资源可接受时才试运行 SafeGuard-VL 7B。
3. 建立 DeepSeek Harness adapter，限制为事件采集和兼容性测试，不允许它直接写入权威安全记忆或绕过 Cedar。
4. 在一次性 VM 中 POC Snyk Agent Scan，与自研 Skill/MCP 扫描器进行差异分析。
5. 修复长上下文窗口：精确 tokenizer 计数、重叠分段、全局摘要、跨段风险聚合、头中尾采样、guard/main-model 上下文一致性。

交付物：Agent 调用序列 benchmark、多模态基线、Harness 事件适配器、长上下文抗溢出报告。

### P3：90-180 天，建立持续对抗能力

1. 部署隔离 MUZZLE 环境，使用可重置 The Zoo/数据库开展 Web Agent 间接注入季度红队。
2. 使用 Confundo 测试 RAG 投毒，构建知识文档签名、来源信誉、摄取时扫描、chunk 级 provenance 和检索时风险过滤。
3. 必要时引入 PyRIT 进行多轮自适应红队；避免与既有用例重复消耗。
4. 自研 RST-Guarder 类层次聚合，但以中文句段和证据图实现，不依赖未维护的英文 parser。
5. 跟踪 CHILLGuard、FIPI、AttriGuard、ShieldMCP 的真实代码、许可证、模型和 release；只有全部满足门禁后才进入候选池。

交付物：持续红队平台、RAG Trust Gate、跨段风险聚合、季度技术观察清单。

## 7. 验收指标

### 7.1 法律和供应链门禁

- 代码、模型、数据三类许可证均有归档，允许目标商业交付方式。
- 所有二进制、容器、模型、规则库和数据库均固定版本与 SHA-256；禁止 `latest`。
- 每个制品有 SBOM、漏洞结果、来源证明和升级/回滚记录。
- 私有化部署在断网环境可完整运行；出网域名为显式 allowlist，默认无遥测。
- 无 LICENSE 的论文仓库不得复制、改写后伪装为自研或随产品分发，只能依据论文思想独立实现。

### 7.2 安全效果门禁

- 使用独立中文金标集报告每类 precision、recall、F1、FPR、FNR，不只报告总体准确率。
- 正常业务拒答率、过度阻断率和高风险漏报率分别设门槛，并按租户/策略版本回归。
- 覆盖直接越狱、间接注入、编码/混淆、长上下文溢出、RAG 投毒、工具投毒、Skill/MCP 供应链、跨 Agent 泄漏和多模态时序攻击。
- 攻击生成模型与判定模型分离；关键结果抽样人工复核。
- 测试集保留隔离集，防止把 benchmark 样本混入训练后得到虚假提升。

### 7.3 性能和可靠性门禁

- 在目标一体机硬件上分别测单组件和全链路 P50/P95/P99、吞吐、显存、内存、冷启动和并发退化。
- 在线组件超时不得造成无限等待；失败策略按风险级别设置，涉及外发、执行和敏感资源访问时默认拒绝或转人工。
- Qwen3Guard、Presidio、NeMo 等 sidecar 必须支持健康检查、限流、熔断、背压和版本回滚。
- Streaming 检测必须覆盖已提交与未提交边界，不能只检查固定字符尾窗。
- token 预算必须由目标 tokenizer 计算，不能继续使用 `字符数/4` 作为安全边界。

## 8. 最终推荐清单

### 立即纳入产品路线

1. Cedar-Java：在线确定性 Action Firewall。
2. Qwen3Guard-Gen：中文/多语言语义护栏影子模式。
3. Presidio：PII/DLP 增强 sidecar。
4. Promptfoo + garak：产品安全回归和独立模型扫描。
5. Trivy + ModelScan + YARA-X：镜像、依赖、模型和扩展供应链门禁。
6. MaliciousAgentSkillsBench：Skill/MCP 测试语料和规则来源。

### 隔离 POC 后决定

1. MalSkills：跨指令和代码的 Skill 依赖图分析。
2. NeMo Guardrails：retrieval/tool rail 参考实现。
3. ToolSafe 的 TS-Guard：工具调用序列风险模型。
4. SafeGuard-VL：多模态策略自适应模型。
5. DeepSeek Harness：Agent 兼容、会话事件和运行时研究。
6. Snyk Agent Scan：MCP/Skill 风险覆盖对照。

### 只用于红队/测试

MUZZLE、Confundo、ACE、FragFuse、ObliInjection、ConjunctiveAgents、DTR、MEval，以及论文中尚无稳定实现的 ToolHijacker、Prompt Overflow、Guardrail DoS、Video-Driven Prompting 方法。

### 暂不采用

CHILLGuard、FIPI、AttriGuard、ShieldMCP、AIOpsShield、MASLeak 等尚无可验证完整制品或许可证的实现。对这些项目建立季度复核，不把“即将开源”当作交付承诺。
