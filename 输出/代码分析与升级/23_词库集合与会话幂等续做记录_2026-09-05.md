## 1. 独立词库与整组发布

- 独立 release-set JSON 是传输单元，保留所有分片、来源 SHA-256、许可声明、原词条 ID、复核引用、匹配方式、动作建议、语境测试。
- 收到制品后重新确定性编译，检查根摘要、分片摘要、顺序、数量和复核引用完整性；不能只改外层哈希就跳过内部验证。版本长度与数据库字段保持一致。
- 一个数据库事务写入集合根、全部分片、关键词与审计记录。相同范围、词库、版本和内容重复导入返回原集合；相同版本不同内容拒绝。
- 导入的 reviewed-artifact 仍是数据库 draft。所有集合必须由不同于提交人的有权限账号审批，不因文件写着 reviewed 自动获批。
- 整组 shadow / canary / active / rollback 使用范围内词库族锁、行锁和 expectedRevision。并发激活只允许一个成功。
- 数据库延迟约束在提交时检查分片数量、顺序位置、内容哈希、签名原文与组状态；组内分片不能直接变更成员身份。单片 API 也显式拒绝组内分片流转。
- 回滚使用激活时保存的 previousSetId，恢复准确的上一组，不按“最近创建时间”猜测。
- 策略编译在同一只读一致性快照中校验集合和关键词；根缺失、分片缺失、混合状态、词条被禁用、分数/强制标记/匹配方式等偏离签名原文均拒绝编译。组摘要和片号写进签名包。
- /dictionaries 已增加整组导入、独立审批、SHADOW / CANARY 登记、编译源选择与回滚入口；普通分片列表只查看，不提供单独流转按钮。

注意：词库的 active 是“下次签名策略包编译源”，不是“已经影响实时流量”。登记 SHADOW / CANARY 本身也不等于已执行影子推理或分流。真实流量仍由现有签名策略包发布及 applicationPolicyBindings 控制。

### API 与权限

| 接口 | 权限 | 请求 |
| --- | --- | --- |
| GET /api/policy-governance/release-sets | policy:read | 最近 200 个集合摘要 |
| POST /api/policy-governance/release-sets | policy:write | { artifact: 完整编译制品 } |
| POST /api/policy-governance/release-sets/{id}/approve | policy:approve | { expectedRevision, reason } |
| POST /api/policy-governance/release-sets/{id}/shadow 或 canary | policy:publish | { expectedRevision, reason } |
| POST /api/policy-governance/release-sets/{id}/activate 或 rollback | policy:publish | { expectedRevision, reason } |

所有写接口沿用鉴权、CSRF、应用范围、频率限制和审计。集合 API 请求体最大 16 MiB，界面文件最大 15 MiB；超大制品不能绕过保护拆成单片发布。集合 state 和 revision 需要刷新后操作。

## 2. 会话幂等及比较机制

- 持久化回执键为客户/应用范围 + sessionId + requestId + direction；不仅记住最后一个请求，因此三轮后重放第一轮也不会再次入账。
- 内容、模型策略包、主体/授权上下文、业务场景、信任封套及动作意图均参与带密钥 HMAC。仅传输 traceId 和绝对 deadline 刷新不改变请求身份。
- 同一个键换内容、换策略或换授权上下文，返回冲突，不能覆盖原回执。策略切换后的新检测请使用新 requestId。
- 会话事件、状态、风险账本与检测结果回执同事务提交。空会话也使用事务锁，避免没有行可锁时重复写入。
- 已完成的重放在引擎调用前返回同一 decisionId，不重新调用模型、不增加风险次数。并发相同请求即使已开始计算，也只提交一次，并返回胜出的结果。
- /api/v1/guard/evaluate 在鉴权和活动包校验后、资源扣费前查询已完成回执。在途重复仍可能由资源准入返回 409；客户端应稍后重试，不能换内容复用 ID。
- 兼容入口生成稳定的封套 ID；此前随机封套会让完全相同的重试变成不同请求。traceId 也已保证满足协议最小长度。
- 回执结果分块 AES-256-GCM 加密保存，不保存原文型请求指纹。到期拒绝重放；保留任务清除过期加密载荷，结束会话时清除该会话回执载荷并使回执到期。
- 最小回执墓碑仍保留用于拒绝过期 ID 重用。其最终清理、客户整体删除及备份到期策略须在客户数据生命周期方案中明确，不能把载荷清理宣称为所有副本已删除。
- 当前密钥 ID 不匹配时不会使用错误密钥或默认为新请求；需要部署侧保留/迁移密钥，或按受控流程开启新会话。

重放是取回原检测结果，不是新的工具执行或交易授权；工具/交易消费者仍必须实施自身的执行幂等和有效期检查。没有 sessionId 的请求本批次没有新增持久化回执；请求 ID 在流式场景的分片规则仍需专项验证。

### 影子比较

治理影子对比中的新旧引擎读取同一份 SecureMemorySnapshot，并且都使用 readOnly；返回 sessionSnapshotVersion 和 sessionMemoryMutated=false。独立 /api/v1/guard/evaluate-shadow 同样接入只读会话检测，不污染正式风险状态。

这不表示所有旧入口已完全等价：原生请求与兼容请求若具有不同的封套、stage 或授权语义，本来就不能直接视为同一请求。还需补齐跨 HTTP 入口、RAG / 工具及流式的完整映射验收。
