## 执行指令（可整体复制）

你是本项目的实施工程师。请实际完成专项方案中的本地代码、测试、数据工具链和验证制品，不只总结方案。

工作目录：`E:\大模型安全\大模型护栏`。首先完整阅读根 AGENTS.md 及目标子目录规则，然后阅读上方详细方案、任务 JSON、拟议门禁 JSON、前置复核报告；以本次实际工作区与只读数据库快照为准。方案标注“新增”的文件/字段/命令尚未实现，不可假设存在。遇到实现变化，记录证据和替代路径，不照搬失效行号。

必须实现的结果：

1. 治理后的独立词库通过签名包进入主 Guard Engine V2，不把整库硬编码到业务或前端代码。
2. 词法候选与确定性强制规则分开；弱关键词误拦能经上下文复核纠正；零关键词风险也接受语义检测。
3. 白名单局部、可审计，不能免除其他风险、其他位置或 mandatory；支持性自伤路由不是检测豁免。
4. 裁判灵活支持 DeepSeek、GLM、Qwen、Kimi、Ollama 及其他本地私有/兼容模型。独立配置 provider、modelId、端点、认证、数据边界、方向/场景、主备、提示模板与预算。
5. 复用 providers/chat.ts、secretRef 和出站控制；私有性不由模型品牌或 Ollama 类型推断；private-only 失败不能切云；云模型不可获得的权重哈希不得伪造。
6. 模型响应经过严格结构校验。拒答、空内容、JSON 错误、截断、未知标签、超时都不是 SAFE；供应商自报 confidence 不是可直接比较的概率。
7. 裁判确实进入签名包和主 V2 DAG，不只修改旧独立裁判；编辑 provider 草稿不能改变 active 行为；旧包保持兼容。
8. 多轮、输入/输出、DLP、工具、RAG、流式和实际支持模态有对应证据；不能仅在单轮文本样例上宣称整体能力达标。
9. 精确率/召回率/误报率/漏报率与动作正确率分开统计；复核、错误、UNKNOWN 和覆盖缺口单列；不以全部拦截或全部转人工“达标”。

实施顺序：

- 从 T00 开始，完成只读基线、工具/脚本和资源核对，不改变 active 策略。
- 按任务 JSON 的 dependsOn 推进 T01—T18。默认顺序见详细方案第 10 节；每个任务采用“最小失败测试 → 实现 → 回归 → 证据记录”。
- T07 必须按 T07.1 配置/迁移、T07.2 多提供商/主备、T07.3 真实分类适配、T07.4 自测与故障矩阵分别记录。没有凭据也先完成不依赖凭据的工程，但不伪造真实测试通过。
- T02 工具链/MVP 可以支撑下游工程；T13/T18 的质量验收必须满足完整独立标注、锁定集、切片数和真实模型证据。
- 每项记录到 `data/content-safety/reports/optimization/<真实 runId>/<taskId>.json`，并据实更新任务状态。不要把尖括号模板直接放进 shell。
- 任务证据包含：基线提交/差异摘要、修改文件、实际命令及退出码、关键断言、制品哈希、工程/质量/部署三种状态、阻断项与下一步。
- 遇到模型账号、GPU、独立审批或真实数据缺失，明确标记对应部分 blocked/INSUFFICIENT_EVIDENCE，同时推进依赖满足的其他工作；不要伪造已完成依赖。

工程约束：

- 仅用 pnpm；修改 Next.js/React 应用前先阅读本地 `node_modules/next/dist/docs/` 对应指南。
- TypeScript 按 strict 编写，不引入隐式 any 或 as any；UI 复用现有 shadcn/ui；契约改源文件后再生成。
- 使用 apply_patch 修改文件；保留所有既有用户改动，不 reset、不强制覆盖。数据库迁移采用向后兼容方式并先在隔离测试数据库验证。
- 可下载完成任务所需、许可清晰且已授权的公开数据与模型资料，固定来源/版本/哈希；先审查，不执行网络脚本，不把候选自动标为 reviewed。
- 不自动购买 API/GPU 资源，不代表用户接受新协议，不把机密或未授权业务原文上传外部模型；没有独立标注者时不能自签 gold 审核。
- 本地实现和隔离测试不授权生产部署、真实灰度切流、外部消息或不可恢复操作；需要这些权限时提交待执行清单及审批点。
