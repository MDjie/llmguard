## 6. 未执行的真实性能测试

PER-001～006、AVA-001～005 没有得到性能或可用性 PASS。本机没有 k6，也没有以下必要输入：

- 冻结的 2000 黑样本、2000 白样本及第一次检测结果；
- 目标信创集群、全量生产策略、目标模型和 API Credential；
- 单节点/集群拓扑、Prometheus 资源采集、300 个控制台账号；
- 故障注入授权、两地三中心环境、备份集及业务 BIA。

因此本轮只完成脚本和报告判分逻辑验证，未输出任何虚假的 P99、QPS、误报率、99.99% 或 RPO/RTO 数字。

新增性能自动化覆盖：

- `guard-fast-path.js`：默认 20QPS，可配置 200QPS，30 分钟，P99<300ms；
- `concurrent-sessions.js`：由健康探测改为 3000 个真实 Guard evaluate 会话并校验 trace 隔离；
- `console-concurrency.js`：300 个认证控制台用户查询；
- `validate-performance-report.mjs`：统一校验黑白样本、分类器、主链 P99、QPS、持续时间、错误率、会话、控制台、CPU、内存和扩容中断。

## 8. 交付判定

当前可交付物是“工程验证基线与修复计划”，不是“功能性能全部验收完成”。最终完成必须同时满足：

1. `coverage-audit.json` 中 101 项全部转为带签名证据的 PASS；
2. 真实多模态、RAG、Agent、SSO、PKI/SOC 和信创集成完成；
3. 六项性能、五项可用性及安全合规报告达到附件指标；
4. 所有外部报告绑定代码版本、镜像 digest、配置 digest、数据集 digest 和时间范围；
5. 失败结果不可覆盖，复测必须保留原失败记录。
