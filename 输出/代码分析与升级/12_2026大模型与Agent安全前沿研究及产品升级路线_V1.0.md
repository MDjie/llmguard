# 2026 大模型与 Agent 安全前沿研究及产品升级路线 V1.0

> 调研日期：2026-09-03
> 适用项目：GuardLLM / AI 安全一体机
> 证据范围：2026 年正式期刊论文、USENIX Security 2026、NDSS 2026、ACL 2026、CVPR 2026，以及全球代表性产品的官方技术文档。

## 1. 核心结论

2026 年最重要的技术变化不是出现了更大的内容分类模型，而是安全边界从“检查输入和输出文本”扩展到了完整 Agent 执行链：

1. 不可信数据必须携带来源、信任级别和敏感度标签，不能与系统指令混在同一个无类型上下文中。
2. 每次工具调用都必须证明它来自用户意图，而不是来自网页、RAG 文档、日志或工具返回值中的隐藏指令。
3. 长期记忆本身已经成为攻击面，攻击者可以跨多轮拆分恶意意图，再通过检索重组绕过单轮检测。
4. RAG 安全不能只扫描最终提示词，必须覆盖文档进入知识库、切块、索引、检索、拼接和生成后的完整链路。
5. Guardrail 自身也会遭受超长上下文、推理放大和资源耗尽攻击，必须具备预算、降级和失败关闭机制。
6. 最有价值的产品升级不是再增加一组正则规则，而是建设“上下文信任平面 + Agent 动作防火墙 + 分层安全记忆 + 持续攻击验证平台”。

建议把下一代产品定位为：

> **面向 LLM、RAG、MCP 和 Agent 的统一运行时安全控制平面，而不仅是大模型内容审核网关。**

## 2. 证据分级说明

- A 级：2026 年顶级同行评审会议正式论文，如 USENIX Security、NDSS、ACL、CVPR。
- B 级：2026 年正式期刊论文。是否属于用户所在机构认定的 SCI/SCIE 分区，应在立项或申报时通过 Web of Science Master Journal List 再核验。
- C 级：2026 年 arXiv 预印本，只作为技术预警和实验方向，不作为已被同行评审的结论。
- P 级：厂商官方产品文档，用于分析已产品化的能力，不将营销描述等同于独立测评结果。

## 5. 最值得投入的十项产品能力

### P0-1：可信上下文与数据溯源平面

为每个进入模型的片段建立结构化信封，而不是把所有内容拼成字符串：

```ts
interface ContextEnvelope {
  envelopeId: string
  tenantId: string
  sessionId: string
  sourceType: "system" | "user" | "rag" | "tool" | "memory" | "agent" | "file"
  sourceId: string
  trustLevel: "trusted" | "controlled" | "untrusted"
  instructionCapability: "allowed" | "data-only" | "forbidden"
  sensitivityLabels: string[]
  contentHash: string
  parentEnvelopeIds: string[]
  policyVersion: string
}
```

核心规则：

- RAG、网页、邮件、日志、工具结果默认是 `data-only + untrusted`。
- 数据片段中的命令不能提升为 Agent 指令。
- 摘要、翻译和模型派生内容必须继承父数据的最高风险与敏感度。
- 所有下游判断能够回溯到原始内容哈希、来源和策略版本。

价值：这是 ACE、间接提示注入、跨 Agent 攻击和审计能力的共同基础，也是与普通内容审核 API 拉开差距的关键平台能力。

### P0-2：意图绑定的 Agent Action Firewall

每次工具调用前构造 `ActionIntent`：

```ts
interface ActionIntent {
  userGoal: string
  proposedTool: string
  proposedArguments: Record<string, unknown>
  targetResources: string[]
  sideEffect: "none" | "read" | "write" | "execute" | "external-send"
  requiredPrivileges: string[]
  supportingEnvelopeIds: string[]
  riskBudget: number
}
```

判定流水线：Schema 校验 -> 用户意图一致性 -> ABAC/能力权限 -> 敏感数据流向 -> 风险预算 -> 高风险动作反事实验证 -> ALLOW、REWRITE、APPROVAL 或 BLOCK。

高风险动作才启用 AttriGuard 类影子重放，以控制成本；普通动作由小模型和确定性策略快速判断。安全反馈应返回可修改的参数或替代工具，使 Agent 能安全重规划，而不是一律终止任务。

### P0-3：128K 分层安全记忆

不能通过保存最近 128K Token 直接实现。推荐四层结构：

1. 原始事件日志：不可变、加密、可回放，保存消息、RAG、工具和策略事件。
2. 热上下文窗口：保存最近交互，用于低延迟检测。
3. 结构化风险账本：保存实体、意图片段、敏感数据、权限变化、工具副作用和累计风险。
4. 篇章/关系图：对长文本建立段落关系和攻击证据边，使用 RST-Guarder 类层次聚合。

记忆写入前检测，召回后再次检测；把当前输入、召回内容和历史风险片段做组合分析，专门覆盖 FragFuse、Context Stitching 和多 Agent conjunctive attack。

### P0-4：RAG Trust Gate

覆盖以下检查点：

```text
上传/抓取 -> 文件与 URL 检测 -> 内容规范化 -> 注入/DLP 扫描
          -> 来源信誉与签名 -> 安全切块 -> 建索引
查询 -> 检索异常检测 -> 每片段复扫 -> 跨片段组合检测
     -> 带溯源拼接 -> 生成 -> Groundedness/引用一致性检查
```

关键能力包括离线批量预扫、投毒隔离区、文档版本和内容哈希、异常相似度检测、跨来源多样性、敏感度继承、引用级响应验证。

### P0-5：自保护的多级级联检测

建议采用：

```text
L0 确定性规则/Schema/哈希/权限：微秒到低毫秒
L1 小型分类模型：Prompt Guard 2 或同等级自研模型
L2 中文/多语言 Guard 模型：Qwen3Guard 等候选
L3 上下文推理与动作归因模型：只处理不确定或高风险事件
L4 形式化策略验证：监管、金融、保险等可形式化场景
```

每层都必须有独立超时、Token、内存和并发预算。超时策略按场景选择 fail-closed、降级模型或人工审批；不得默认悄悄 fail-open。Guard 模型和业务模型必须采用一致的规范化、截断和窗口覆盖证明，避免 Prompt Overflow。

### P1-1：持续自适应红队

- 从固定攻击库升级为基于执行轨迹反馈的攻击生成。
- 覆盖直接/间接注入、RAG 投毒、工具链、MCP、跨轮记忆、多 Agent、文件、图像、音频和视频。
- 每次模型、策略、解析器、工具或知识库变更自动回归。
- 将生产匿名事件转化为可复现攻击种子，但不得泄露客户数据。
- 输出 ASR、任务成功率、误拒率、攻击成本和最短成功轨迹。

### P1-2：MCP、Skill 和模型供应链安全

- MCP Server、工具定义、Schema、示例文本、工具输入和输出全部扫描。
- 生成权限清单：网络域名、文件路径、命令、凭据、写操作和外发能力。
- 插件和模型进行签名、SBOM、反序列化风险、恶意代码、后门和许可证扫描。
- 在隔离环境进行动态行为分析，检测凭据访问、外连、持久化和隐藏能力。
- 版本变化自动产生权限差异和风险差异，未经批准不得上线。

### P1-3：策略编译与自动推理验证

把自然语言政策编译成版本化、可测试的规则中间表示：实体、变量、前提、约束、例外和结论。高价值场景对模型输出中的声明做一致性验证，返回 `VALID`、`INVALID`、`AMBIGUOUS`、`INSUFFICIENT_CONTEXT`，并附带证据路径。

适用场景：金融销售话术、保险条款、医疗流程、政务回答、内部权限规则。它不能替代内容安全模型，但能显著提升“为什么阻断”和“是否符合业务制度”的可解释性。

### P1-4：多模态时序安全

- 图片：OCR、视觉语义检测、隐藏文字、二维码/URL、文件元数据。
- 音频：ASR 文本检测、超声/不可听指令检测、说话人和时间段溯源。
- 视频：不能只抽固定帧；使用镜头切分、关键帧 + 连续帧窗口 + OCR/ASR 融合。
- 文件：PDF/Office/Markdown 的可见文本、隐藏层、链接、嵌入对象和宏分别检测。

多模态策略应作为运行时参数，而不是固化到模型权重中，从而支持不同客户、地区和行业标准。

### P1-5：量化安全保证与证据中心

建立可签名的发布门禁：

- 策略覆盖率和未映射规则数。
- 已知攻击、未知变体、自适应攻击和跨语言攻击的 ASR。
- 良性任务完成率、误拒率和策略改变前后差异。
- P50/P95/P99 延迟、吞吐、并发、内存、Token 成本和超时率。
- RAG 引用正确率、Groundedness、敏感信息泄漏率。
- 每个判断的模型、规则、阈值、输入哈希、证据和策略版本。

没有完整证据的测试项只能标记为“未验证”，不能进入产品性能宣传。

## 7. 与当前产品的关键差距

当前系统已经具备 GuardEngine V2、多检测方向、结构化 DLP、会话风险状态、流式提交门、API/会话级限流和策略包基础，这是升级的良好起点。主要差距是：

1. 会话上下文仍偏向尾部文本，没有实体级风险账本、来源关系图和跨轮恶意片段重组检测。
2. RAG/Tool 虽有检测方向，但缺少从摄取、切块、索引到检索后的完整来源与投毒治理。
3. 工具调用缺少用户意图绑定、能力令牌、参数级数据流和反事实动作归因。
4. 限流集中在请求和 Token，缺少 Agent 资源生命周期、工具递归和 Guard 自身成本治理。
5. 尚未形成模型、MCP、Skill、知识库和策略包统一供应链准入。
6. 红队主要是测试集合，缺少轨迹反馈、自适应攻击、跨步骤和跨模态攻击生成。
7. 缺少正式的策略编译、发布签名、性能证据和可复现安全保证报告。

## 8. 六个月落地路线

### 阶段 0：基线与架构冻结，第 1-2 周

- 固化当前功能、准确率、误拒率、ASR、P99 和资源占用基线。
- 建立统一 `ContextEnvelope`、`RiskEvidence`、`ActionIntent`、`GuardVerdict` 契约。
- 将所有截断、跳过检测、模型错误和降级路径纳入审计。
- 输出覆盖矩阵和不可宣传项清单。

退出条件：所有 Guard 请求都可标识租户、应用、会话、来源、策略和 Trace。

### 阶段 1：长上下文与 RAG Trust Gate，第 3-8 周

- 原始事件日志 + 热窗口 + 风险账本 + 关系图四层记忆。
- 对 128K 输入实施重叠分块、篇章关系聚合和 Token 覆盖证明。
- 建设知识库摄取扫描、隔离、内容哈希、来源信誉和检索后复扫。
- 引入 FragFuse、ObliInjection、Context Stitching 和 Prompt Overflow 测试。

退出条件：不存在未检查但会送入业务模型的 Token；跨轮攻击测试具有稳定可复现结果。

### 阶段 2：Agent Action Firewall 与 MCP Gateway，第 7-14 周

- 工具 Schema、描述、参数、响应和凭据扫描。
- 实现意图一致性、ABAC/能力令牌、数据流、风险预算和审批。
- 对外发、写入、执行、权限变更类动作启用反事实验证。
- Guard 返回可执行修复建议，支持 Agent 安全重规划。

退出条件：所有有副作用动作在执行前获得带证据的授权决定；工具返回内容不具备指令权限。

### 阶段 3：级联模型与流式/多模态，第 11-18 周

- 评测 Prompt Guard 2、Qwen3Guard 及内部模型，按语言和场景校准阈值。
- 建设风险路由，低风险走快速模型，高风险进入推理或形式化验证。
- 改造流式安全状态机，支持 Token/句子级提前阻断和完整响应复核。
- 增加文件、图片、音频和视频时序扫描。

退出条件：在目标硬件上达到明确的 P99、吞吐和误拒率门槛；任何检测组件不可用时行为可预测且可审计。

### 阶段 4：持续红队、供应链和量化保证，第 15-24 周

- 实现轨迹感知攻击生成、失败反馈变异和多轮工具链攻击。
- 建设模型、MCP、Skill 和策略包扫描、签名及准入门禁。
- 建立 Detect -> Canary -> Enforce 策略发布流程和自动回滚。
- 生成可签名的客户验收报告和版本级安全保证报告。

退出条件：模型、策略、插件和知识库任一变化都会自动触发相应安全回归；上线版本拥有完整证据包。

## 9. 建议的验收指标

以下是研发目标，不是当前能力声明：

| 指标 | 建议目标 |
|---|---|
| 已知直接注入 ASR | <= 1% |
| 未见语义变体 ASR | <= 5% |
| RAG/Tool 间接注入 ASR | <= 5%，高风险动作 <= 1% |
| 跨轮记忆重组攻击 ASR | <= 5% |
| 良性任务完成率下降 | <= 3 个百分点 |
| 中文关键场景误拒率 | <= 1%，按行业分别统计 |
| 长上下文 Token 检查覆盖率 | 100%，不得静默截断 |

## 11. Build / Borrow / Integrate 决策

必须自研并掌握权威状态：

- Context Trust Plane 和风险溯源协议。
- Secure Memory 风险账本和跨轮聚合。
- Agent Action Firewall、权限与数据流策略。
- 策略版本、证据、审计和验收体系。

适合吸收开源组件或模型：

- Prompt Guard 2 作为轻量快速检测候选。
- Qwen3Guard 作为中文、多语言和流式 Guard 候选。
- NeMo Guardrails 的五阶段 Rail 思路，但使用本项目自己的权威策略引擎。
- DeepSeek Harness 作为可选 Agent Runtime、事件回放和测试环境。
- 成熟的 OPA/Cedar 类策略执行器、容器沙箱和可观测性组件。

适合做厂商兼容连接器而非绑定：

- Model Armor、Bedrock Guardrails、Microsoft Foundry、Prisma AIRS、Check Point 和 Cisco。
- 使用统一 Guard 协议允许客户选择本地引擎、第三方 SaaS 或双重判定。

## 12. 最终建议

未来六个月应把研发重心从“增加更多敏感词和分类标签”转到三个不可替代的产品资产：

1. **可证明来源的上下文安全图谱**：知道每段内容来自哪里、能否成为指令、携带什么敏感度以及如何传播。
2. **意图绑定的逐动作零信任防火墙**：每个 Agent/MCP 动作执行前都完成权限、数据流、因果来源和风险预算判断。
3. **可验证的长上下文安全记忆**：在 128K、多轮和多 Agent 场景下保持完整 Token 覆盖、攻击碎片关联和可回放证据。

这三项一旦落地，产品将从常见的“输入输出过滤器”提升为真正的 Agent Runtime Security Platform，也是对标国际头部厂商时最有技术壁垒、最能支撑一体机溢价的方向。
