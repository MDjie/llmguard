# V1.1 剩余任务执行计划

基线：main `082d09a`，2026-09-08。承接已提交的 P0—P6 工程增量，不重复建设告警、归档、派生证据和反馈候选入口。

## 用户补充决定

联合裁判采用 **GLM-5.3**。官方模型卡提供文本生成接口，因此先用于具有来源坐标的 OCR/ASR/字幕/上下文联合语义判定；原始媒体专项检测独立保留。派生证据的联合判定不能签发原生媒体完整覆盖资格。

模型标识、部署端点、权重或服务版本、提示词、策略和数据边界必须进入资格绑定。实际部署别名可能为 `glm-5.3` 或 `zai-org/GLM-5.3`，配置显式指定；不静默回落至其他版本。旧模型质量批准不能沿用。参考：[官方模型卡](https://huggingface.co/zai-org/GLM-5.3)。

## 按依赖顺序执行

| 编号 | 剩余任务 | 工程交付及验收条件 | 外部依赖 |
| --- | --- | --- | --- |
| R1 | GLM-5.3 联合裁判 | 来源绑定、局部证据映射、严格输出、失败关闭、现有规则约束不被清除；独立模型与提示词资格 | 实际端点、模型版本、数据出域批准、凭据引用 |
| R2 | 媒体变换 | 图片/画面遮挡、音轨静音、时间裁剪；严格计划和原件摘要、真实解码、派生摘要和逆时间映射；越界/多轨/失败拒绝 | 格式与硬件质量验收 |
| R3 | 输出复检释放 | 原件与派生物归档、全对象复检、OUTPUT 资格、请求/策略/路由绑定、一次性许可；任何变更和撤销拒绝 | 合格的原生检测器、目标业务模型 |
| R4 | 金融正式样本 | 沿用现有工作台独立签名、分组和锁定集；GLM-5.3 实测及分风险指标 | 专业复核人员与真实样例 |
| R5 | 运行验收 | 当前代码回归、存储读写/恢复/冻结/删除、容量、HA、24 小时和 W12 证据检查 | 客户测试存储、部署拓扑、硬件与容量目标 |

## 执行边界

先完成可在仓库和隔离环境复现的工程项；缺少真实模型或人员签名时，保留明确的待验收项。候选、工程夹具和解码通过不等于真实识别质量通过。继续 main 工作，保留已有本地资料。每个工作包记录具体变更、验证命令和真实结果，最终全库回归后更新执行清单。
