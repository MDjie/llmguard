### 2 E0 基线修复与合并后复验

E0-1 修复契约生成的跨平台字节一致性。当前 gateway-v2.schema.json 工作区使用 CRLF，生成器按原始字节计算摘要，清单摘要为 121c28d9…；main 提交中为 LF，摘要为 d9f2cfd9…。生成器输出 LF，工作区签出产物为 CRLF，逐字比较又产生额外漂移。隔离副本重生成显示 Zod 与 OpenAPI 字段一致，其余差异仅为摘要字面量和清单哈希。不得仅执行生成覆盖后就宣布解决，也不得用 --accept-baseline 消除本问题。

处理方案是对自有契约 schema、生成器、生成产物及镜像 proto 设置明确的 text eol=lf，保持第三方 source-lock 文件的 -text 规则；仅对列明文件执行受控归一化，再运行现有生成器并检查差异。若摘要写入多语言产物，全部相关产物、镜像 proto 和 manifest 必须同批更新。保留兼容基线，追加 Windows 与 LF 检出的一致性检查，确认 pnpm contracts:check 及兼容检查通过。仅改变格式和摘要不应触发字段兼容破坏；若发现字段变化，独立审查后再处理。

E0-2 复验发布刷新边界。main 的 publication.ts 已将旧 WINDOW 资格校验限定于非 refresh 或恢复旧快照。补数据库回归：显式刷新 WINDOW 到 FULL_BUFFER 成功；自动续期、回滚、撤销恢复仍拒绝失效资格；并发 generation 冲突及签名快照绑定不回退。复用 check-gateway-v2-publications.ts，不将当前静态代码判断计为数据库通过。

E0-3 恢复隔离链路后复跑 TEXT 文件与基础代理。核查环境文件存在性、数据库名称与端口、TLS 证书、工程资格有效期和进程健康；不打印配置中的密钥。复用 with-gateway-v2-profile.ts 选择 FULL_BUFFER，并依次运行 check-gateway-v2-artifact-model.mjs 与 run-gateway-v2-e2e.mjs，保留脚本退出码及逐项结果。该 wrapper 在 finally 恢复原资格并再次刷新，结束阶段失败也算失败。准备阶段端口未监听，恢复环境作为实施前置，不擅自连接生产库或改客户资格。

E0-4 检查 Compose 0057/0058 分别挂载为 67/68 的现状，并跑当前提交的契约、类型、lint、全量单元和必要集成。仅有文本挂载检查不证明数据库初始化成功；实际镜像启动、离线包、HA、24 小时长稳和 W12 仍按原待办保留，不因本次执行计划而标记完成。

### 3 P0a 首个功能修复单元

修改范围先限制在 src/lib/multimodal/fusion.ts、src/lib/media/timeline-fusion.ts 及其现有测试。把 B04 的两条 exact 强制拒绝样例正式迁入对应测试，断言最终 BLOCK、单路证据仍存在且坐标准确。先证明测试在原 main 失败，再实现修复；复现脚本中的“期待旧缺陷”断言不能直接充当修复后验收。

合并规则先保留全部适用单路决策的终止约束，再处理联合结果、视觉、失败与覆盖；联合正常不能解除已确认单路强制拒绝。证据从各自分支的 spans 映射到原对象后再去重，不能拿 combined.spans 映射单路 offset。去重键含风险、来源对象、坐标、规则或判定来源及内容版本，同一词在不同对象中的命中不能被误合并。原文仍仅通过已有 HMAC 和脱敏片段表达。

增加对照：只有联合命中仍保留联合证据；单路与联合都命中不重复膨胀；无内容模态不凭占位符产生业务风险；覆盖不足与单路 BLOCK 同时出现仍为 BLOCK；必需分析失败仍阻断。运行引擎、多模态、媒体相关测试与类型检查，验收通过后再进入 P0b。

迁移 aggregate.ts 时保留风险前缀阈值、outputDirection 与 actionOverrides 的原行为；纯词法兼容策略不能被无条件要求裁判而全场阻断。SAFE_RESPONSE 不能清除人工审核要求；高分输出若配置 MASK/REWRITE 且复检通过，仍允许安全派生内容按原契约释放。若要对外新增状态字段，先更新契约 schema 和生成结果，再调整消费者，不能手改生成文件。

方向从调用方传到每个子判定，不只修改函数内部常量。异步旧入口明确 INPUT 语义；新增业务输出入口显式映射 OUTPUT_COMPLETE、OUTPUT_CHUNK 或 TOOL_RESULT。输入输出不同策略、兼容旧签名 DAG、复检链路和缺覆盖处理必须同时回归。时间窗口改造属于 P1/P4，不塞入 P0a 的首个修复。

## 本批落地设计补记

### 动作、方向和证据

实际新增 `src/lib/guard-engine-v2/action-constraints.ts`。集合合并优先级为 BLOCK > REQUIRE_REVIEW > SAFE_RESPONSE > REWRITE > MASK > WARN > ALLOW；内部同时记录原文释放限制、审核、替代响应、MASK/REWRITE 变换需求及复检要求。文字聚合与两类融合直接复用集合合并，排序常量仅用于联合攻击诊断和代表性结果选择。对外 GuardAction 保持不变，原有高分输出 actionOverrides 和完整复检继续生效；内部约束不是释放许可。

调用参数在原 context 上兼容可选 direction，默认 INPUT；两个异步 worker 显式传 INPUT。缺少可选模态时生成 MODALITY_NOT_APPLICABLE 标记，不调用检测器扫描占位符；evidenceComplete 为 false，不构造“已完整检测”的证据。必需分析失败和 coverage-v1 的分析资格检查仍在融合层执行。

图文保留 user/image/codes/combined，媒体保留 user/audio/subtitles/frames/codes 与所有时间簇的命中证据。局部 textStart/textEnd 使用 JavaScript UTF-16 索引、左闭右开区间，是 OCR/转写片段中的字符位置；时间坐标仍使用分析器给出的片段区间，不能解释成逐词强制对齐时间。去重在映射回来源后执行，并包含检测器/规则版本、风险、内容 HMAC、动作、坐标与 trace；不同图像对象及不同时间片段不互相覆盖。媒体 `decisions.combined` 仍展示代表性联合结果，不能据此代替 evidence 中的全部时间簇。

### P3 四种内容归档、恢复与访问

已实现 RECEIVED_INPUT、MODEL_INPUT、MODEL_OUTPUT、RELEASED_OUTPUT 四类版本：控制面接收事务持久加密暂存，发送及释放前必须持久确认，Java 在模型路由映射后记录实际供应商请求、响应映射前记录原始响应，SSE 原始事件按序保存并确认尾序号。记录发送意图不等于模型收到，释放意图也不等于客户端收到；最终完整性同时核对实际执行回执、内容引用和序号缺口。

对象执行条件写入、固定版本回读、密文摘要校验；归档清单确认后才清空暂存。独立归档 worker 负责重试、终态对账、每日版本检查和 180 天到期清理。存储版本不可读会产生归档故障告警、阻止完整性声明；恢复后按同一版本重新验证。持有冻结与未消费原文访问授权阻止删除，删除证明保留对象版本和备份处理状态，备份未验收时明确 PENDING_EXTERNAL。

文件/RAG 准备后的检测上下文额外作为 RECEIVED_INPUT / CONTENT_SEGMENTS 保存，确保发送前拦截仍能还原实际检测文本；它不等于实际模型输入。新增 `/conversations` 最近 180 天请求与会话内容版本列表，复用双人审批、一次性消费和 60 秒临时查看。原文高亮只使用服务端验证的路径、摘要、内容版本与 UTF-16 偏移，不把原文偏移套在脱敏预览上。历史上未归档的对话不会自动变成完整记录。

默认归档模式仍为 DISABLED，STRICT_OBJECT 按应用启用。单个归档内容最多 4 MiB JSON，每请求密文暂存/对象总量最多 64 MiB；超过预算失败关闭并显示缺口，不能声称无限长度流式记录。S3 语义依据 [PutObject 官方接口](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) 和 [GetObject 官方接口](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html)。当前验证使用版本化回环对象存储夹具，未代表客户 S3、备份、灾备及 180 天真实运行通过。

### P4 原始联合分析与执行许可

`native_joint` 任务冻结所有原始对象、摘要、所属应用和用户、上下文、方向与策略版本；分析服务通过固定命令适配器同时加载原件，OCR/ASR/采样与原始联合裁判分别记录。联合结论为 CONFIRMED / SUSPECTED / NOT_DETECTED / UNKNOWN，启发式关系只能为 SUSPECTED。跨对象关系引用必须落到绑定对象；资格按模型摘要、分析器版本、策略、方向、模态组合、风险覆盖、评测集摘要和有效期匹配。

输入发送复用现有签名 artifact-context 和网关状态机：`guard_artifacts` 各引用增加同一 native_joint jobId，核对原件顺序和摘要、任务完成时间、上下文、冻结路由及 live 资格后才物化模型请求。需 STRICT_OBJECT 并先归档原件；外部 URL 不可替代原件身份。当前原生传输明确限制为总计 1 MiB，图片 png/jpeg/webp/gif、音频 wav/mp3、视频 mp4，路由须有独立格式资格，未登记默认拒绝。格式依据 [OpenAI Chat Completions 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 与 [阿里云视觉模型官方接口](https://www.alibabacloud.com/help/zh/model-studio/vision)，不推断任意模型同时支持全部模态。

联合正常不能解除规则或单路 BLOCK / REQUIRE_REVIEW。现有音视频辅助分析为 SAMPLED，缺少合格完整分析时仍可能保持人工审核；输入改写必须重新提交联合任务，不复用旧上下文资格。原生输出媒体隔离已接线：先保存模型原始响应，再抛出 NATIVE_OUTPUT_REVIEW_REQUIRED，状态转为 REVIEW_REQUIRED，生成不可自动恢复的待判定告警，未产生释放回执。外部媒体 URL 没有原件时归档为 GAPPED；中断的媒体 SSE 也显示尾部缺口。取得资格后的原生输出释放，以及区域遮挡、静音、裁剪后新对象复检尚未实现；当前使用设计第 7.6 节允许的阻断回退。真实裁判命令、目标模型与硬件效果待客户环境验证。

### 告警投影故障恢复

每条记录通过保存点隔离。仅把可确定的数据错误（契约不合格、摘要/身份不一致、SQL 数据/外键约束失败）转为 FAILED；网络、死锁、存储满及其他事务故障保留整批回滚重试。FAILED 保留原始不可变 payload 与 digest，仅记录固定错误码，不保存 SQL 参数或异常原文；不会阻塞后续正常告警。

`pnpm alerts:recover --tenant <tenant> --application <app>` 只读查询 FAILED 元数据，最多 100 条，后续使用返回的 `--after <nextAfterId>`。修复缺失引用等根因后，使用 `--retry <recordId> --actor <operatorId> --reason <至少10字说明>` 重置为 PENDING。操作在同一事务内追加审计链、递增 retryCount，保留上次失败信息，不允许重写判定 payload。摘要损坏的记录不能靠重试修好，应排查来源并产生新的正确记录。当前只在隔离工程库试验过重试。

### 历史回填使用边界

`pnpm alerts:backfill --tenant <tenant> --application <app> --source GATEWAY|GUARD_JOB|LEGACY --from <ISO时间> --watermark <ISO时间>` 默认只读预览，每页最多 100 条，返回 nextAfterId；后续页使用相同水位和 `--after`。确认的工程执行加 `--apply`；必须按应用范围操作，最多覆盖 180 天。已有投影跳过，不覆盖原始证据；已过期或无法验证的历史判定明确返回 skipped，旧客户端记录保持 UNDETERMINED。原文未归档的历史记录不伪造新档案。当前只在隔离工程库执行过带写入的验证。

### 覆盖和证据的最后修正

`semanticQualified` 表示资格记录匹配，`semanticComplete` 表示这次分析真正完整；SAMPLED 不因为有资格就变成完整。已清除的候选词不再投影成风险告警。OCR/ASR 的 contentVersion 使用具体派生文本 SHA-256，sourceDigest 仍绑定原始媒体，避免把原件版本误当作转写版本。当前授权高亮已贯通网关文本和准备后的检测上下文；未存储的媒体派生文本不能声称可重放或可精确高亮。

### 派生证据的保存和恢复

新增 0063 `media_evidence_snapshots`，使用与任务一致的 varchar(36) job_id 及租户/应用复合外键。图文、音视频和 native_joint worker 从实际参与检测的文本片段生成私有 EvidenceView；任务公开 result 仅保留证据位置和归档摘要。严格归档模式下，任务终态、告警 outbox 与派生证据密文暂存在同一事务提交；任一失败整体回滚。

EvidenceView 保存原件 SHA-256、派生文本 SHA-256、UTF-16 路径与版本、视图、页、区域、时间及音轨信息。每个来源必须属于任务绑定的原件或上下文，并校验所有者、应用、有效期及摘要；native_joint 还对照冻结的来源摘要。相同词在不同来源或不同时间段不去重为一条。临时保存、上传及回读均有 4 MiB 明文预算和 10000 视图/映射上限，超限失败，不假装完整保存。

状态机为 PENDING → OBJECT_WRITTEN → READY → DELETE_PENDING → DELETED。对象条件写入后按固定版本回读，确认密文摘要再转 READY，最后清除数据库密文暂存。上传确认丢失时重试同一对象；维护 worker 重试、每日检查、生成存储故障告警并处理到期删除。保留期从 job.createdAt 起算 180 天。冻结的到期档案继续检查对象版本；删除受冻结和未消费有效原文授权约束。删除证明绑定对象版本、密文摘要、时间及备份处理状态，其摘要进入审计链。备份状态 PENDING_EXTERNAL 不是备份已删除。

原文审批资源增加 MEDIA_EVIDENCE。用途不同的待批申请不能互相复用；批准时取得来源共享锁，和到期清理互斥。读取失败不消费授权；成功消费后只能临时展示 60 秒。已过期且未冻结、已删除、来源摘要变化的资源不可读取。独立媒体任务保存的是派生文本，不能据此宣称原始上传文件也保留了 180 天；网关 native 请求另将原件和派生快照复制进四类对话归档。

### 坐标和授权回放

图片分析器对旋转、增强与裁剪视图记录来源尺寸和逆仿射矩阵，OCR、二维码、标签与视觉区域在输出前转换到显示方向一致的原始页。奇数尺寸裁剪使用整数边界和 exact=1，避免色度取整改变位置。坐标基准是显示方向一致的源页，不是相机传感器坐标。音频保留变速比例和反向时长，时间映射回原音轨；视频保留实际采样时刻和帧号。

原生请求发出前必须读到 READY 的派生快照，并校验策略和任务绑定；快照缺失时不发出 SEND。归档序号为：原始请求 0、原件 1…N、准备后检测上下文 N+1、派生快照 N+2。原件附带来源坐标证明，不将私有转写文本放入普通告警列表。

授权高亮逐一校验来源摘要、派生版本、路径、视图、坐标、文本长度和 UTF-16 边界。原图区域框还须匹配归档中的来源证明和逆映射版本；GIF 不按静态帧假定区域。音视频跳转仅在浏览器已加载元数据、且时间落在已验证源时长内时启用。ASR 时间是片段范围，不代表逐字强制对齐。浏览器编码不支持会显示解码失败提示；记录和检测结论不因此丢失。

### 反馈进入评测候选

新增 0064 `feedback_candidate_exports`，只保存租户/应用、反馈、一次性授权、资源、来源 HMAC、候选摘要和操作者，不保存明文样例。界面路径为“安全告警 → 处置与反馈 → 独立确认反馈 → 反馈转评测候选”。选择派生证据或对应输入/输出归档版本，以 FALSE_POSITIVE_APPEAL 用途申请独立原文审批；批准后选择文本来源并下载候选包。

导出须同时满足：反馈为 triaged、独立复核 ACCEPT、提交者身份与复核记录一致、复核 sourceDigest 与当前反馈全部判定字段一致、资源属于该告警的任务/请求及方向、原文授权属于当前操作者且来源版本一致。多命中视图必须明确选取；受控接口另支持严格 JSON Pointer，拒绝原型链路径和非字符串字段，单条上限 16000 字符。

授权消费、反馈共享锁下的再验证、不可变导出台账及审计事件在同一事务内完成。校验失败回滚授权消费；响应在网络中丢失但服务端已提交时，需要重新申请授权。输出经隐私脱敏，为 needs_review、零金标签名、authorizedExternalUse=false；来源性质区分 customer/synthetic。派生文本候选不代表原生多模态金标。

下载结构与现有 `dataset-workbench` 一致。多包使用前必须汇总候选、进行来源分组/近似去重和开发/锁定集拆分，再由独立人员签名；不要在已签名后改分组或拼接未经重新校验的锁定集。正式质量报告和发布仍使用既有工作台及策略治理流程。本次没有把候选包自动送入线上词库。
