## 给开发、部署和测试同学的执行顺序

1. **补齐认证后的部署信息。** 页面 URL、公开构建标识、前端调用接口已确认。由测试/部署人员在已登录环境记录构建提交或镜像标签、后端服务版本和实际数据响应；或先提供该页面导出的脱敏 CSV。不要在对话或报告中发送数据库密码、Cookie、API 密钥等凭证。
2. **导出并备份。** 使用截图页面的“导出”功能取得现有词库，保留恢复副本；对外提供脱敏的表头、字段结构和这 3 条注入样例即可。核对是否包含隐藏的停用记录、维度编码、分类、匹配方式、分数、策略关联和共享标识。
3. **确认数据与代码的差异。** 检查目标 API 返回总数、筛选参数、分页、启用状态和读取的数据源，再判定是数据缺失、发布遗漏、过滤映射还是缓存/版本问题。不得仅凭截图选择某一种根因。
4. **映射并预演，先不写入。** 把候选映射到已确认的导入 schema；按目标唯一键去重，保留已有用户词条、启停状态及策略配置。输出拟新增、重叠、冲突和待人工判断的数量。合并后的条数不一定等于 147，不能把固定总数作为验收条件。
5. **审核处置，不能全量硬拦截。** 截图严格策略警告阈值为 30、阻断阈值为 60，原 3 条分数为 95/90/95。不能将全部新短语赋为 90 或 95 直接启用；也不能认为 60 分就是“仅候选”。目标前端缺省和 0 分均转成 90，不要依赖低分导入代替审核。若目标共享词表仅支持 contains + 分数硬处置，应先扩展候选/语义复核能力，或保持词条待审、停用或仅影子观测。组合模式与短语应区分，不能把正则文本导入 contains 字段。
6. **经审批实施更新。** 确定可审核、可回滚的导入/发布路径后，在目标测试环境合并共享词库，保持各策略独立阈值。新代码内置模式必须通过服务构建发布才能生效；只导入候选不会升级引擎，只部署前端不会补齐数据库。
7. **端到端验证并留证。** 核对页面计数、API 计数、实际运行检测器版本/策略绑定；刷新或重新登录后再次确认。对正例、正常问询、引用分析和否定表达逐一记录最终动作、命中证据、语义复核状态和请求方向。
8. **验收与回滚。** 保存构建版本、导入批次、变更前后计数、运行策略、脱敏测试结果及回滚步骤。出现异常时回滚本批次资产/构建，不删除历史词库或覆盖客户策略。生产启用需独立业务标注和验收，本次自编回归不替代该验收。
